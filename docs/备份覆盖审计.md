## 四、缺口表（没被备份的东西 + 风险 + 建议）

### 🔴 高
1. /home/j/.ssh/id_ed25519 私钥完全没进任何备份层
   - 证据：全量归档 tar 顶层只有 payload/posix/home/j/.openclaw，/home/j 下其它路径（含 .ssh）条目数为 0。
   - 风险：这是访问 NAS（192.168.1.5）恢复入口的钥匙；若本机磁盘全毁，连 NAS 上的归档都取不回。
   - 建议：把 .ssh 私钥加密后纳入备份（或离线打印/存加密 U 盘）；给 NAS 侧留备用恢复通道。

### ⚠️ 中
2. ④ L2 git 层 4 个工作区推送失败（非快进冲突）+ 主 workspace 没配 remote
   - 证据：nas-git-push.sh 报告「成功16 · 跳过1 · 失败4」；失败的 class-schedule / mom-health / schedule-doudou / script-mystery 报 rejected (fetch first)；NAS ws-*.git 这 4 个目录 mtime 停在 09-24 04:34。
   - 另：workspace（主工作区）git remote get-url origin 为空 → L2「跳过1」= 它，git 层不上 NAS。
   - 风险：这 4+1 个工作区 git 历史层在 NAS 陈旧；但文件内容仍被 ① 归档 + ③ repos 镜像兜底，暂无数据丢失。
   - 建议：对 4 个工作区 git fetch origin 后合并再 push；给主 workspace 配 origin remote。

3. ① 全量归档中 agent 原始 sqlite 只有 3/22
   - 证据：归档内 agents/*/agent/openclaw-agent.sqlite 仅 doll-brand / main / openclaw 3 个；本地共 22 个。但归档内嵌 backup-repo/agents/ 有 21 个 agent 目录 + global，按表 dump 成 jsonl。
   - 风险：raw 库层不完整；若依赖 raw sqlite 恢复会缺 19 个库，需走 jsonl 重建。
   - 建议：确认 openclaw backup create 是否应把全部 agent 库 raw 打包；或恢复文档明确 jsonl 重建路径。

### 🟢 低（housekeeping）
4. ⑤ 备份统一整理从未运行（status idle）→ 保留策略/清理从未真正执行。
5. /home/j 非 .openclaw 部分：.npmrc（可能含 npm 凭证）、.gitconfig、.bashrc 未备份；旧 openclaw-backup/(564M) remote 指向 /mnt/c/Users/J/Desktop/openclaw-backup.git（已废弃，冗余可清理）。
