## 一、秘书（双顾问）已改为配置驱动，换模型不用改代码

- 配置文件：`state/advice/advisors.json`（不在代码里硬编码）
- 每个顾问一条：`label / kind(anthropic|openai) / url / model / secret / max_tokens / cap / focus / enabled`
- `secret` 只写**密钥库里的名字**（如 `KIMI_API_KEY`），密钥本身不出现在任何文件或对话里
- `kind` 两种协议都支持：`anthropic`（x-api-key + messages）与 `openai`（Bearer + chat/completions），国产厂商基本都覆盖
- `enabled: false` 即停用；新增一个顾问＝往 json 里加一段，不用重启、不动代码
- 调用：`python3 tools/advice-ask.py --plan … --advisor qwen|glm|all|逗号列表`；`--advisor all` 会跑所有启用的顾问
- 已预置但未启用的槽位：kimi、doubao（豆包）、ernie（文心）、gemini（需代理）
- 预算表按配置里的 `cap` 自动生成，新加顾问不会撑破旧预算逻辑（state/advice/budget.json）

实测：改配置后 glm 顾问正常返回（2026-11-22 12:23，state/advice/20261122-122355-glm.md）。

### 2) 稳定性/可用性（2026-11-16 ~ 11-22 实际运行）

- deepseek-flash：39 个管家主力，7 天 13,639 次调用（83.2%），成本 ¥26.5（79.8%）；24h 任务 1,845 次、失败率 0.33%。**唯一有持续大规模样本的模型**。
- glm-5.3：7 天 1,919 次（11.7%），成本 ¥3.8；Coding 套餐周用量约 17%，几乎不会因为额度中断。
- qwen4-max：仅作顾问（4 次调用/3 次采纳），单次 12–39 秒；Token Plan 12-01 到期，余额 93.4%。
- kimi：11-20 已从全部链路移除（额度耗尽），历史 9.33 分但不稳定（曾有 0 字节空回）。
- minimax：余额耗尽，M 计划纯文本、图像需另计费，**不建议再续**。
- 本地 ollama：仅作最后兜底，扛不住多步工具调用。

### 3) 结论：智能 + 适用面

**deepseek-flash 是当前"最智能且最适合"的那一个**——自测质量第一，价格最低，7 天 1.3 万次调用的实测稳定性最好。glm-5.3 第二，强在风险审（顾问角色），且套餐不占现金。qwen3.8-flash 纸面分数接近，但缺长期样本。
