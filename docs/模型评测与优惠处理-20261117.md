# 模型评测与优惠信息怎么处理（2026-11-17 定）

## 原则：信息必须带「到期/触发条件」才算处理完
只记录不发动的评测与优惠等于幻觉。每条信息落库时必须带 `expires_at` 或 `trigger`，以及一句 `action`。

## 三个台账（模型管家维护，我只读+落地）

1. `docs/模型评测台账.md`（主本在 workspace-model，主区软链）
   - 每模型一行：能力（文本/推理/视觉/上下文长度）、实测分数、测试任务、耗时、成本、样本量、测于何时
   - 硬要求：每条结论附一条可复跑的命令或任务 id；没有复现方式的分数不进台账
   - 用途：只服务一件事——支撑 `routing.json` 里的每一条首选/备选

2. `state/model-econ/promos.json`（结构化，机器可读）
   - 字段：provider / models / type(discount|reset_card|plan_expiry|quota_pack) / window / expires_at / action / status
   - 类型只有四种；`reset_card` 这类稀缺资源必须写「什么条件下才准用」
   - 每日扫描：7 天内到期、已过期未用、阈值触发（如周额度>90% 才准用重置卡）

3. `state/model-econ/routing.json`（路由唯一真源）
   - 按活型分：主力重活 / 轻活轮询 / 评审 / 长文 / 图片理解 / 翻译
   - 每项：首选、备选链、理由（引用评测台账的条目）、成本档
   - 我只从这里取配置；配置与 routing.json 不一致时以文件为准并回改配置

## 每天它给我一张「可执行清单」
- 今天/本周到期的优惠与额度（带剩余天数）
- 触发条件的动作项（例：GLM 周额度>90% → 用重置卡）
- 评测缺口（新模型进池 7 天未测、关键模型 30 天未复测）
- 路由建议变更（附带评测依据）

## 分工
- 模型管家：产出上面三个文件 + 每日清单，不改任何 agent 的 model 字段
- 果果：把清单落成 config patch（dry-run → 金丝雀 → 回滚），维护 `main` 自己的模型分配
- 主公：花钱、换供应商、改套餐
