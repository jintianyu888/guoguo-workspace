# 白话：鉴权与错误兜底（2026-11-22，主公说要讲懂）

> 不讲术语，只讲「是什么、在哪、坏了会怎样、我怎么提示你」。

## 一、鉴权（Authentication）＝ 门禁
- 大白话：谁可以进、进来能干什么。三层：①你是谁（认人）②你能进哪扇门（授权）③你进来后能做什么（权限）。
- 你系统里的五道门：
  1. 网关 18789：靠一串 token（相当于总钥匙），没钥匙连不上。
  2. 面板 8899：靠 IP 白名单（只认家里这几个地址），别的地址访问直接 403。
  3. 飞书机器人：靠 open_id 白名单（每个机器人眼里你的 ID 都不一样，这是今天剧本杀管家不回复的原因）。
  4. 管家执行命令：靠审批白名单（哪些程序允许跑；不在名单上就拒）。
  5. 密钥库：API key 存加密库，我读得到但不会回显，也写不进聊天。
- 危险点：面板那道门目前是「认地址不认人」（S0046）——同一个 Wi-Fi 下的电脑都能调；这是 P0，已列根治。

## 二、错误兜底（Error handling / Fallback）＝ 保险丝
- 大白话：一条路断了，自动换下一条，而不是整个炸掉。
- 你系统里的兜底例子：
  1. 模型兜底链：deepseek 挂了自动换智谱 → 再换本地 ollama。
  2. 语音兜底：云端 TTS 失败自动回本地 F5（今天实测过，能降级成功）。
  3. 备份兜底：一份写完校验再删暂存；副本不存在就不许删。
  4. 升级兜底：新版本自检不过自动回滚旧版。
- 反面例子（最危险的一类）：假活/假绿——服务 HTTP 返回 200 但数据库已挂；任务记「成功」但产物不存在。对策：真写探针 + 校验产物，不只看状态码。

## 三、坏了你会看到什么
- 「连不上」：网关 token 或端口转发坏了（WSL 重启后常见）。
- 「面板 403」：你的 IP 不在白名单（换了网络就会）。
- 「机器人不回复」：99% 是 open_id 白名单不匹配，不是它笨。
- 「couldn't finish」：那一轮超时或工具调用失败，重发一次通常就好。
- 「告警重复」：同一故障反复出现 = 有根因没治，看反复故障清单。

## 四、我会怎么跟你说
- 涉及鉴权/兜底的改动，我先说三句：改哪道门、谁能进、最坏会怎样。
- 每次复发都提示一次，不默默修；你要么说「止血」，要么说「根治」。
- 不用你记术语，你只要问「这道门现在谁能进」我就答。
