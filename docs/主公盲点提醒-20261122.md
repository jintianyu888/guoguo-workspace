# 主公盲点与提醒清单 · v1.0（2026-11-22）

> 来源：主公 2026-11-22 21:18 令「以你对我的了解，给我找问题与盲点，日常对话可以提醒我」。
> 用法：果果在日常对话中按第 3 节触发条件提醒；不做说教，只提醒一次，附可执行动作。
> 证据口径：每条后面括号是出处，不写「我觉得」。

## 1. 六个盲点（按影响排序）

1. **下完指令等不到回执就重发/催问**
   - 现象：同一条指令 20:32 与 21:09 各发一次；20:22 追问「好了么」。
   - 代价：同一件事被重复触发，我这边要额外确认是不是新需求，白耗一轮。
   - 对策（我的义务）：收到即回「收到，预计 X 分钟，卡住会先说」。你只需等这一句。

2. **同时抛多条线，不给优先级**
   - 现象：权限审核、剧本杀、面板横幅、盲点盘点在同一小时里并行，我只能按「谁先坏先修」排。
   - 代价：你真正着急的那条可能排在后面。
   - 对策：你发多条时加一句「先 X」；不加时我默认按「服务不可用 > 数据风险 > 功能缺陷 > 优化」排，并在回执里说明我排的顺序。

3. **容易采信「看起来对」的完成报告**
   - 现象：我曾报「备份已修」而实际是旧脚本的陈旧状态；报「已归档」而未校验 SHA256。你当时都直接采信了。
   - 代价：假绿比失败更贵，事后返工。
   - 对策：我的每条完成报告固定三件套——结论、验证命令与输出、回滚方式。你说一句「验了吗」即可抽查。

4. **对根因耐心少于对「先能用」的需求**
   - 现象：网关内存、Code Mode 桥、备份链路这类结构问题，多次是打补丁后继续跑。
   - 代价：同一个故障反复出现（今天 16 次超时、面板横幅反复）。
   - 对策：我每次给两个选项——止血（X 分钟）与根治（Y 小时+窗口），你说一个字选。

5. **待拍板事项没有固定过一遍的时间**
   - 现象：S0046（面板零鉴权）/S0047（无错误兜底）挂 300+ 小时；权限、密钥、花钱类长期悬着。
   - 代价：风险敞口一直在，且越拖越难改。
   - 对策：每周日 20:30 简报里我加推一条「待你拍板 ≤5 条」，只列要你一句话的，不列过程。

6. **表达常省略指代，需要我回问一次**
   - 现象：「用的时候再补吧」「还是不行」这类，我得先确认指哪件事。
   - 代价：多一轮往返。
   - 对策：我按最近上下文猜并写明「你指的是 X，对吗」，猜错你只要回「不是」。

## 2. 你的强项（别改）
- 决策快、敢授权：说「可以」就放手，我才能一次做完。
- 认证据不认话术：我编数字你会追。
- 成本敏感但不抠：知道该花的窗口（半价时段、订阅取舍）。
- 对「重复造轮子」零容忍：这条逼出了技能库。

## 3. 提醒触发条件（我执行）
- 你重复同一句话 → 我不辩解，直接报当前进度与卡点。
- 我交付完成 → 必带验证输出；你说「验了吗」我立刻给命令与结果。
- 多线并行 → 回执照我的排序来，并标「如需改序说一声」。
- 结构性问题复发 → 主动给「止血/根治」二选一。
- 周日 20:30 简报 → 待拍板清单（≤5 条）+ 本周新盲点。
- 你说话有歧义 → 我先猜再确认，不反问三次。

## 4. 边界
- 只提醒、不评判人格；同一盲点一天最多提一次。
- 你明确说「不用提」的，本会话与后续不再提，除非复现造成实际损失。
- 本清单不写进主公手册正文，避免与你的自述混淆；手册仍是你自己写的口径。
