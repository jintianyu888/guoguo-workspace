# 企业微信（WeCom）接入 OpenClaw —— 方案研究报告（v2，按真实验收标准重估）

> 日期：2026-09-25 · 状态：只读调研，未改动任何配置
> 验收标准：`docs/wecom-requirement.md` —— 不是「接回调」，是**在群里干活**
> 本次更新：新增「对着需求打分」一节；查证了智能机器人群聊能力、会话内容存档、群机器人 webhook 三项。

---

## 0. 结论速览（TL;DR）

1. **验收标准变了**：不是「回调验签能不能过」，而是「果果能不能在**含微信个人号的群**里收文件、回话、打印」。
2. **只有一条路能同时满足「收 + 发 + 打印」且不付费**：**智能机器人（Bot/长连接模式）进群**。官方文档已确认它支持群聊、支持收/发 file/image/voice/video，且长连接模式**无回调验签**。
3. **决定成败的只有一个未知数**：智能机器人**能否加入「含微信个人号的客户群/外部群」并收到微信用户的消息**——这一步必须实测（10 分钟能出结果），过不了则方案 A 废。
4. **自建应用（Agent 模式）读客户群消息，必须开通「会话内容存档」（付费、需企业认证、拉取式非实时）**——这解释了为什么修好回调也没用。
5. **群机器人 webhook 只出不进**（单向推），且通常只能内部群——只能做「果果主动通知」，做不了「收文件」。
6. **兜底**：飞书群（功能当天可用，但老板/媳妇要换 App）；或付费会话存档（留在微信/企微生态）。

## 1. 根因分析：`account_not_found`（保留，仍是正确诊断）

### 1.1 插件包位置与版本

- 包：`@wecom/wecom-openclaw-plugin`（本地源码 `~/.openclaw/npm/projects/wecom-wecom-openclaw-plugin-18f843d908/node_modules/@wecom/wecom-openclaw-plugin/dist/`）
- 已装 `2026.7.2` · npm 最新 `2026.9.15`（中间隔了 2026.8.17）
- 依赖 SDK `@wecom/aibot-node-sdk`（提供 `WecomCrypto` 验签）

### 1.2 代码链路与真相

| 文件 | 作用 |
|---|---|
| `dist/src/accounts.js` | 解析配置，判定 `agent.configured` |
| `dist/src/channel.js` | `startAccount`：注册 agent 回调 target / 起 WebSocket |
| `dist/src/agent/webhook.js` | **Agent 回调 HTTP 入口**，`account_not_found` 产自这里 |

1. 配置 `channels.wecom.agent` 四项齐全 → **`agent.configured = true`** → 账号**已注册**（日志「注册 webhook」即证）。
2. `account_not_found` 是**误导性报错**：源码里 `matched.length === 0 ? "account_not_found"`，真实含义是「**用配置里的 token 算出的签名 ≠ 企微发来的 msg_signature**」，不是「账号不存在」。
3. 验签算法 = `sha1(sort([token,timestamp,nonce,echostr]).join(""))`，**标准无误**（你复现的也对，所以多轮都得到同一结论）。
4. 「not connected / 无 WebSocket 日志」是**正常现象**：Agent（自建应用）模式是**被动 HTTP 回调**，本来就不建长连接（只有 `botId+secret` 的 Bot 模式才起 WebSocket）。

### 1.3 已排除 / 已实测

| 项 | 结果 |
|---|---|
| 账号未注册 | ❌ 已注册（源码 + 日志） |
| 公网可达 / webhook 路径 | ✅ 401 = 插件在应答，`/plugins/wecom/agent/default` 已注册 |
| corpSecret | ✅ **gettoken 实测成功（7200s）** |
| token/AESKey 格式 | ✅ 9 位 / 43 位（解码 32 字节），无空白 |
| 验签算法 | ✅ 标准 sha1-sort |
| 插件版本 | ⚠️ 2026.9.15 验签逻辑与 2026.7.2 完全一致（已 diff），升级不解决验签 |

> 结论：回调验签失败 = **配置里的 token 与企微后台「API接收」里保存的值不一致（或 token 取自错误位置）**。但——**这已经不是关键矛盾了**，见下节。

## 2. 关键矛盾：验收标准要求「含微信个人号的群」

老板真正要的两个群：**群① = 老板微信 + 媳妇微信 + 果果(企微)**、群②乐谱群。群里含**微信个人号** → 在企微体系里是**外部群/客户群**。

这一条决定了所有方案的生死：

- **自建应用（Agent）收不到客户群消息**。自建应用的「接收消息」回调只推**内部成员/内部群**；客户群（含微信用户）的消息必须走 **「会话内容存档」**（付费能力）才能拿到。
- **群机器人 webhook 只出不进**，且一般只支持**内部群**。
- **智能机器人（Bot）**：官方支持群聊 + 收/发文件，但**能否进「含微信个人号的客户群」是唯一待验证点**。

**因此：「接个回调」这个目标本身就跑偏了——真正要解决的是「机器人进客户群」这个能力边界。**

---

## 3. 三个关键能力的官方查证

### 3.1 智能机器人（Bot/长连接模式）—— 方案 A 的底气

来源：官方文档《How to Integrate OpenClaw to WeCom Smart Robot》(doc 21657) + 智能机器人 API (doc 101463)。

- ✅ **支持群聊**：回调里 `chattype` = `single`（单聊）/ `group`（群聊）。
- ✅ **收消息类型**：text / image / 图文混排 / voice / video / **file**（文件）。
- ✅ **发消息类型**：markdown / file / image / voice / video / 模板卡片，支持**主动推送**（`aibot_send_msg`）。
- ✅ **长连接模式无回调验签**（官方明确「Use Long Connection 不需要域名/IP 收消息，不像 URL 回调方式」）。
- ⚠️ **限制**：①群聊里需 **@机器人** 才触发回复；②每个机器人**同一时间只能一个长连接**；③**能否加入含微信个人号的客户群，官方文档未明确，需实测**。

### 3.2 会话内容存档 —— 自建应用读客户群消息的唯一官方途径

来源：官方文档 doc 91360。

- 定义：企业**统一设置存档的员工范围**，通过 **API 拉取**开启存档员工的工作沟通内容，用于合规。
- 性质：**付费能力**，需企业认证 + 申请开通；是**拉取式**（非实时推送），文件需另行下载，有延迟。
- 对需求的意义：只有这条路能让「自建应用」读到客户群消息（含微信用户发的文件）。

### 3.3 群机器人 Webhook —— 只出不进

来源：官方文档 doc 91770。

- ✅ 单向**推**送 text / markdown / image / file / voice / 模板卡片，**零验签**（key 藏 URL）。
- ⚠️ 有**发送频率限制**；❌ **不能收消息**；⚠️ 一般仅**内部群**可添加。

## 4. 对着需求打分

> 验收点：①能在含微信个人号的群收到文件/图片/PDF；②能回话/回发文件；③能打印（tools/print.py）；④覆盖群①+群②；⑤成本/复杂度。

| 方案 | ①收文件 | ②回发/回话 | ③打印 | ④含微信号群 | ⑤成本 | 总评 |
|---|---|---|---|---|---|---|
| **A 智能机器人(Bot/WebSocket)** | ✅ 原生支持 | ✅ 原生支持 | ✅ 收到即打印 | ⚠️ **待实测** | 低(免费用量) | **首推，唯一全满足候选** |
| **D 自建应用 + 会话内容存档** | ✅ 存档拉取(有延迟) | ✅ message/send | ✅ 收到即打印 | ✅ 是(存档覆盖客户群) | ❌ 付费+企业认证+开发 | 备选(留微信生态) |
| **E 飞书群承载** | ✅ 飞书已通 | ✅ | ✅ | ❌ 老板/媳妇换飞书 | 低 | 兜底(功能最快) |
| **B 自建应用主动发(message/send)** | ❌ 只发不收 | ✅ 能发 | ❌ 收不到无打印 | 半(发客户群还需外部API) | 低 | 仅做通知 |
| **C 群机器人 Webhook** | ❌ 单向 | ✅ 能推文本/文件 | ❌ 收不到 | ❌ 一般内部群 | 低 | 仅做通知 |

**逐条结论：**

1. **只有方案 A 能同时满足 ①②③④ 且不付费**——前提是「智能机器人能进客户群」这一关过得了。
2. **方案 D** 是「留在微信/企微生态」的正解，但要**付费 + 企业认证 + 拉取式开发**（非实时、文件要单独下载），适合「必须用微信」的硬需求。
3. **方案 E（飞书群）** 功能上当天可达成全部 ①②③，但**老板和媳妇得改用飞书**，脱离微信生态——这是「要不要换 App」的取舍，不是技术问题。
4. **方案 B/C 只能当「果果主动通知/结果推送」的配角**，解决不了「收文件」。

## 5. 各方案落地要点（按推荐度）

### 方案 A：智能机器人 Bot 模式（WebSocket）—— 首推 ⭐

- **原理**：`botId + secret` 走 `wss://openws.work.weixin.qq.com` 长连接（`aibot_subscribe`），**收消息走 WebSocket、无回调验签**；支持群聊 + 收/发文件。
- **落地步骤**：
  1. 企微 App → 工作台 → 智能机器人 → 创建 → **API 模式（长连接）**，拿 botId + secret。
  2. 配置 `channels.wecom.botId` + `channels.wecom.secret`（`connectionMode=websocket` 默认），停用/删除 `agent` 段。
  3. 把机器人加进群①和群②（**这一步即验证客户群是否放行**）。
  4. 重启网关，看日志 `WebSocket connected`。
  5. 群里 @机器人发图片/PDF → 看果果是否收到 → 调 tools/print.py 打印 → 回发文件。
- **凭据**：botId + secret（全新，与 corpId/corpSecret 无关）。
- **优点**：双向收发文件、能进群、无回调坑、插件原生支持、解锁 15 个 wecom 技能。
- **风险**：①客户群放行未定（**唯一生死点**）；②群聊需 @机器人。
- **耗时**：30–60 分钟。
- **是否依赖回调**：否（WebSocket）。

### 方案 D：自建应用 + 会话内容存档 —— 留微信生态的正解（付费）

- **原理**：自建应用 + 开通会话内容存档，通过 API **拉取**客户群消息（含文件），再主动回发。
- **落地步骤**：企业认证 → 申请开通会话存档 → 配置存档范围（果果账号）→ 开发拉取轮询 → 打印/回发。
- **凭据**：corpId + corpSecret + 存档密钥（另有专用密钥体系）。
- **优点**：留在微信/企微生态，微信用户无需换 App。
- **风险**：付费、企业认证门槛、拉取式（有延迟，文件单独下载）、需自行开发轮询+解密。
- **耗时**：数天（含申请审批）。
- **是否依赖回调**：否（主动拉取 API）。

### 方案 E：飞书群承载 —— 功能最快兜底

- **原理**：收发、打印、回发全在飞书群（飞书已 connected，能收文件 + tools/print.py）。
- **落地步骤**：建飞书群，把老板/媳妇拉进飞书，果果直接干活。
- **优点**：今天可用、零新依赖。
- **风险**：老板/媳妇换 App（微信 → 飞书）。
- **耗时**：10 分钟。
- **是否依赖回调**：否。

### 方案 B/C：主动推送 / 群机器人（配角）

- 只做「果果主动通知/结果推送」；**解决不了收文件**。可作为方案 A/D/E 的补充（把结果推回老板企微/微信）。

---

## 6. 推荐结论

- **首推：方案 A（智能机器人 Bot 模式）**。
  - **一句话理由**：它是**唯一**能同时「在群里收文件 + 回发 + 打印」且**不付费、不换 App**的路径，官方已确认支持群聊和文件收发，唯一的悬念是「客户群放行」。
- **决策分叉（按实测结果走）**：
  - 智能机器人**能进客户群** → 方案 A 直接落地，收工。
  - 智能机器人**进不了客户群** → 二选一：
    - 老板/媳妇**可换飞书** → 方案 E（当天达成）；
    - 老板/媳妇**必须用微信** → 方案 D（付费会话存档）。

### 最小验证步骤（10 分钟内出结论）

1. **先建智能机器人**：企微 App → 工作台 → 智能机器人 → API 模式（长连接）→ 拿 botId + secret。
2. **配进 OpenClaw**：写 `channels.wecom.botId/secret` → 重启网关 → 看是否 `WebSocket connected`。
3. **拉进群①测试**：把机器人加进「老板微信 + 媳妇微信 + 果果」的群 → 群里 @机器人发一张图/PDF。
   - 收到 → **方案 A 通关**，接着测打印 + 回发。
   - 加不进群 / 收不到微信用户消息 → **客户群不放行**，按上面分叉切方案 E 或 D。
