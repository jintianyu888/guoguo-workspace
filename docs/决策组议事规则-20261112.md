# 决策组议事规则（v1.0 · 2026-11-12 主公提议后立）

> 主公原话：建一个决策池／决策组，不同模型各是一个管家，拉到群里，做重要决策、互相审核，监督所有管家（包括果果）。

## 一、定位（先把话说清楚）
决策组是**技术决策的合议机制**，不是新的权力机关。三句话定边界：
1. **能监督谁**：所有管家（maint/backup/model/work/hermess/library）的技术动作，以及果果的 L2/L3 改动。
2. **不能监督谁**：主公。主公一句话可推翻任何裁决，决策组无权也无力否决主公。
3. **不能自决什么**：删除/密钥/权限/花钱/重启/对外发送，以及"决策组自己有多大权力"这类元问题——一律主公定。

## 二、席位（按模型家族去重，避免同源同盲点）
- GLM 席：`zai/glm-5.3-flash`｜常规评审，性价比
- Kimi 席：`kimi-coding/kimi-for-coding`｜长文与结构评审
- 本地席：`ollama/gpt-oss:20b`｜离线兜底；**已知限制：上下文 32k，长提案会溢出（11-12 首会即翻车）**，只投短议案
- DeepSeek-Pro 席：`deepseek/deepseek-v4-pro`｜重推理补位，某席失效或需第 4 票时启用
- 提案席：果果（`deepseek/deepseek-flash`）——**提案人回避，不给自己投票**

## 三、议事规则（硬性）
- **L1**：可回滚、不动钱/权限/删除/重启 → 不入会，执行后报备。
- **L2**：改脚本/配置/cron/流程、跨管家协调 → **三席会审，2/3 同意**方可执行。
- **L3**：删数据/改密钥/权限扩容/重启关机/对外发送/付钱 → **四席会审 3/4 + 主公明示**。
- 平票＝**维持现状**，不做动作（不是"那就做吧"）。
- 每次至少一席必须写反方意见（conditions 或 risks 不得全空），防止集体附和。
- 少数派意见原样入账，禁止删改；事后复核要能追到"当时谁反对、为什么"。
- 决策组不得评审自己的权限变更（自我扩权无效）。

## 四、机制（为什么不是靠群里聊天）
飞书群里多个机器人**不能互相 @ 触发**：机器人发的消息不会作为事件回灌给别的机器人。所以真开会靠编排：
1. `tools/decision-pool.py new` 立议案（标题/档位/正文/回滚）
2. 编排者用 `sessions_spawn` 并行拉各席模型（各自独立上下文，互不可见），同一份事实、同一套问题
3. `tools/decision-pool.py vote` 逐席入账
4. `tools/decision-pool.py close` 按档位算裁决；票数不够直接拒绝结案
5. 群里只做**公示**：议案号、各席票、少数派意见、裁决结果

## 五、防退化（这套机制最怕的三件事）
1. **橡皮图章**：三席全 approve 且理由雷同 → 视为一次"无效会议"，需换模型重开。
2. **同源同盲**：三席来自两家厂商也仍可能一起错 → 重大议案要求其中一席必须列"我们可能都错在哪"。
3. **权威漂移**：决策组悄悄扩大自己的权限 → 由主公随机抽查 + 每月复盘时点名。

## 六、账本
- 议案与票：`state/decisions/ledger.jsonl`（唯一真源）
- 席位配置：`state/decisions/pool.json`
- 工具：`tools/decision-pool.py`（new/vote/close/list/show）
- 每次开会结果同步进 worklog，L3 议案同时进 tasks.db

## 八、席位分强弱（2026-11-12 主公问询后补）

「每家旗舰各出一席」——**不建议**。理由与做法：

### 为什么不是每家一席
1. **收益看家族差异，不看档位堆叠**。多一席同族旗舰，多半只会复读同族的盲点；真正涨信息量的是换家族。
2. **旗舰不等于更敢说真话**。对齐更强的模型更倾向给"稳妥、面面俱到"的答案，评审里反而容易滑向附和；便宜模型有时更直给。所以旗舰只在需要深推理时用，不是常备。
3. **开会成本×席位数×档位**。每加一席旗舰，每次 L3 的成本大约翻一截，还会拖慢出结论。
4. **席位数一多，合议就散了**——5 席以上平票和稀泥的概率上升，责任也模糊。

### 现行设计（已落地 pool.json）
- **L2（常规）三席**：GLM 席 `glm-5.3-flash` + Kimi 席 `kimi-for-coding` + DeepSeek 旗舰席补位。快、便宜、结论够用。
- **L3（重案）三席旗舰**：`glm-5.3` + `k3-256k` + `deepseek-v4-pro`，四个家族覆盖三个，长文、推理、性价比都不缺。
- 席位上限 5，常设席不轻易加；本地席保留作断网兜底（32k 限制只投短案）。

### 果果算不算一票
**不算。** 我的角色是提案 + 执行 + 提供事实，给自己投票等于自我背书。
但我保留三项**非投票**权利，因为这类风险只有执行者看得见：
1. **事实质询**：发现评审建立在错误事实上，可要求重开投票（须给证据）。
2. **执行暂缓**：现场判断执行会立刻出事，可暂缓并要求复议——但**不能**用它强行通过一个被否的方案。
3. **自陈盲区**：提案里必须写"我最可能错在哪"，写不出说明我还没想清楚。

### 一条最该加的规矩
**kill criteria**：每席投票时必须回答"出现什么情况就该推翻这个决定"。比"强制反方"有用——强制反方容易产表演性杠精，kill criteria 产的是可执行的止损线。

## 九、开会议案前必须先自证事实（2026-11-12 首案教训，立即生效）

首案 D-20261112-002 的教训：我拿"TMPDIR 未生效、需重启切换"去开 L3，三席都认真评了，但事实本身是错的——TMPDIR 当天 09:08 已生效，且 /tmp 本身就是 tmpfs，议案收益≈0。虽然最后由我行使**事实质询权**作废，没造成损失，但白烧了三席调用。

规矩改成：
1. 议案必须带 **facts_check** 字段：写清"我验过什么、用什么命令验的、输出是什么"。
2. 没验过的事实，只能写成"待验假设"，不能写成结论——写假设就要在议案里标明，评审席会据此给条件票。
3. 提案人自陈盲区照旧：**我最可能错在哪**。
4. 出现事实质询 → 议案作废（void），不是修补后继续用旧票。

## 九、定名与开会政策（2026-11-12 22:33 主公令）

### 名字
正式名 **议会**（内部工具名仍为 `tools/decision-pool.py`，账本 `state/decisions/`）。
为什么叫议会不叫"决策会"：它不做日常决策，只审**高风险议案**；叫"决策会"会让人以为事事要开会，
最后要么开会成瘾、要么形同虚设。议会的定位是——**提出者不投票、席位互相独立、少数意见必须入档**，
像议会而不像董事会。

### 什么时候开（硬性）

**必开 · L3（三席旗舰：glm-5.3 / k3-256k / deepseek-v4-pro）**
1. 不可逆或难回滚：删数据、改权限、改密钥、动网关/网络暴露面
2. 动钱：任何付费、订阅变更、额度调整
3. 对外：发消息、发布、交付外部
4. 全局性配置：cron 上限、模型链、备份保留策略、防火墙、时区/时间表
5. 同一个问题我改过两次还没解决（返工两次＝我的判断已被证伪）
6. 我自报"这里有盲区"的议案

**开 · L2（三席快模型：glm-flash / kimi / deepseek-flash 补位）**
1. 跨机器、跨盘、跨目录的批量操作
2. 多管家协同的排工变更
3. 新机制/新脚本第一次上线（哨兵、看门狗、代理人）
4. 要写进"规则类文档"的变更
5. 库房删除候选清单（任何删文件的事）

**不开 · L1（我自己做，事后报备入账）**
1. 可撤销、只影响单机、无外发的小改（重启面板、加日志、改文案）
2. 纯查询与读取
3. 已经批过的同类操作照办（如继续给下一台机器配对，用同样参数）
4. **紧急止血**：服务挂了、数据在丢，先修后审——**议会不许挡救火**，事后 2 小时内补一份"事后议案"入档

### 护栏
- 每天 L3 最多 3 次（成本≈9 次旗舰调用）；同一议题 24 小时内不重复开
- 每次必须有 kill criteria（推翻条件），否则工具拒收
- 议案必须带 facts（验过什么、什么命令、什么输出），不带的直接拒收
- 裁决不等于放行：删数据/改密钥/改权限/外发/重启，议会通过也**要主公点头**（双门）
- 主公可以推翻任何裁决；主公有最终解释权
- 平票＝维持现状，不改动
