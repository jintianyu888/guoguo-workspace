## 二、问题（主公指出的核心）
1. **同一事实多处记**：任务在两套 DB，告警在 ledger 与 notices 两处，删除在 trash-ledger 与 cleanup-log 两处
2. **没有写入人**：多数 JSONL 只有 ts 和内容，不记谁写的、依据什么写的
3. **无法追查**：改一条记录不留痕，事后无法还原是谁改的
4. **口径不一**：有的记 UTC，有的记本地；有的用秒，有的用毫秒
5. **备份副本混入**：.bak-1024 躺在 docs 下，容易被误当成有效账本读取

## 三、规则（拟）

**R1 一类数据一本账**
每类数据只有一本主账，其余一律是导出或缓存，且必须标注「非真源」。

**R2 每条记录必须带写入人**
字段强制：ts（ISO8601 带时区）/ writer（agent id）/ action / subject / detail / content_sha256 / trace_id
缺 writer 或 trace_id 的记录视为无效。

**R3 只走唯一写入口**
禁止 echo >> / sed -i 直接改账本；一律通过 ledger-ctl.py（或各账本的专用 ctl 脚本）写入。

**R4 链式哈希**
每条记录存 prev_hash，形成可校验的链；断链即报警。

**R5 备份副本不得混入**
.bak / .bak-1024 一律移到 state-backups/，docs 下只留有效账本。

**R6 每日校验**
ledger-audit 每日跑：条数一致、链不断、无孤儿、无重复真源；不通过则报「台账不可信」。

## 两家一致同意的方向
单一真源、写入人留痕、防篡改、每日校验——方向都对。

## 必修一：链式哈希必须受并发控制（zai 修 1，minimax 必修一）
两家都指出：按草案写法，链式哈希在并发写入下必然分叉。
可复现场景（zai）：两个进程同一秒各调一次 ledger-ctl 向同一 JSONL 追加，
都读到同一个 prev_hash=H_n，各自追加，产生两条指向 H_n 的记录——链分叉。

改法：
- **所有走链的账并入 SQLite**（WAL 模式，busy_timeout=5000），靠事务串行化
- 链不放在 JSONL 文件里，放数据库表内，写入在同一个事务完成
- 审计必须检测两类异常：**分叉**（同一 prev_hash 有多个后继）与**截断**（尾记录被删）
- 只验「prev_hash 有前驱」不够，那种校验对分叉静默放行

## 必修二：迁移必须有流程和水位（两家都提）
**停写 → 快照 → 校验 → 切换 → 观察**，五步缺一不可。
- 分批迁：先迁低风险表，再迁告警/删除等高价值表，每批独立链
- 迁移水位：记录每本账已迁到第几条，中断可续，不重不漏
- 幂等：每条记录带唯一键，重复导入不产生副本
- 时间口径统一 ISO8601 带时区，禁止本地时间与 UTC 混存

## 必修三：旧库与文档的处置（zai）
- **state/tasks/tasks.db：废止作为真源，保留只读归档，不删除**
  步骤：导出全部行带 orig_id → 去重并入 ledger.db → chmod 0444 → 移入 state-backups/
- **Markdown：正文不必入库，事实必须入库**
  交叉验证、模型评测的每条结果记录抽成结构化事件（带 trace_id）进 DB，
  .md 降级为数据库导出的报告，不得作为唯一记录
- 纯讨论纪要可留 Markdown，但一旦包含任务结论或责任承诺，必须转结构化事件

## 最终架构（定）
1. **主账**：state/ledger/ledger.db（SQLite WAL），所有事实记录的唯一真源
2. **导出/缓存**：JSONL 一律降级为非真源，文件头必须写「非真源，勿直接读」
3. **报告**：Markdown 只做人类可读导出，由数据库生成
4. **写入口**：只走 ledger-ctl 类脚本，禁止 echo >> / sed -i
5. **身份**：每条记录强制 ts(ISO8601 带时区) / writer(agent id) / action / subject / trace_id / content_sha256
6. **校验**：每日 ledger-audit，查分叉、截断、孤儿、重复真源、时间口径；不过即报「台账不可信」

## 迁移顺序（本周起）
1. 建 ledger.db 新表结构 + 链式审计（不迁数据）
2. 低风险表先行：shutdown-alert / maint-notices / cleanup-log
3. 高价值表：alerts / trash-ledger / backup-hash / cloud-backup
4. tasks.db 归档退出（只读保留，不删）
5. Markdown 台账转为导出物
6. 每批走停写—快照—校验—切换—观察，观察期 24 小时

## 不做的事（明确排除）
- 不删任何旧账本（保留只读归档）
- 不在迁移中改变记录语义，只做搬家+补字段
- 不在高峰期做迁移（属 L3，且涉及数据完整性）
