# 管家计划—审核—验收制度（日/周/任务计划）

> 版本 v1.0 ｜ 2026-10-31 ｜ 主公令：管家每天交计划，果果审核双审后批准，管家执行，成果汇报，靠这个循环进化

## 一、适用管家（第一批）
- 模型管家 model（选型/测评/额度/评审池/接替表）
- 备份管家 backup（备份链/盘位/保留/恢复演练）
- 维护管家 maint（体检/告警转达/进程健康）

第二批（本周内）：安全、日历、信息窗、做饭、乐谱库、健康三兄弟、税务、理财。

## 二、一天的时间轴（与时间表真源一致）

| 时刻 | 谁 | 做什么 | 产出 |
|---|---|---|---|
| 06:50 | 管家 | 交当日计划 | workspace-<名>/state/plan/日计划-YYYYMMDD.md |
| 07:00–07:25 | 果果 | 审核：合法性（撞不撞窗）、必要性、可验证性 | 批准/打回，逐条写理由 |
| 07:25–07:40 | 果果 | 高风险项走双审（两家不同厂商，真跑完） | 双审结论入台账 |
| 07:40 | 果果 | 下发批准单 | state/plan/批准-YYYYMMDD.md |
| 07:45–08:15 | — | 重启红区，不许排任何活 | — |
| 08:20–18:00 | 管家 | 按批准单执行 | 每条任务的 exit code + 产出物 |
| 18:30 | 管家 | 交成果汇报 | state/plan/成果-YYYYMMDD.md |
| 18:40 | 果果 | 验收：证据四件套（exit code / 独立探针 / 产出物哈希 / 时效） | 通过/不通过，入账本 |

## 三、计划必须长什么样（缺一项就打回）

1. **事项**：一句话说清做什么
2. **依据**：为什么现在做（告警、主公令、定期维护）
3. **时间窗**：几点做、预计多久（必须有近 7 天实测，没有实测就打回）
4. **验证命令**：可判定、看 exit code，不接受“应该可以”
5. **风险等级**：L0/L1/L2（见第四节）
6. **回滚**：失败怎么退

## 四、分级审批（解决“每次改动都要双审”的矛盾）

zhipu 评审指出：每天几十次增改不可能每次都等两个模型。机械分级如下：

- **L0 免审**（留痕即可）：新增/关闭普通任务、改备注、补用途说明、只读巡检
- **L1 双审**：改时间窗、改保留策略、改脚本逻辑、动 cron、跨目录搬文件
- **L2 三审**：删除、权限扩张、密钥、重启/升级、账本结构变更

分级由脚本判定，不靠人判：涉及关键词（delete/rm/retention/restart/permission）自动升 L2。

## 五、账本怎么接
- 每条计划 = 账本 tasks 表一条记录，assignee 填管家名，verify_cmd 必填
- 批准单、成果汇报各写一条 events 记录，形成可追溯链
- 每周五 18:00 管家交周计划，果果汇总成一页纸给主公（完成率/打回率/告警闭环率）

## 六、进化机制（这是主公要的核心）
- 每周统计每个管家：交计划准时率、打回率、验收通过率、误报率
- 连续两周打回率 >30% → 说明它不会做计划，果果给它改模板，不骂人
- 连续两周 100% 通过 → 放宽它的 L0 自主范围（少审几条）
- 出现一次假绿/假红 → 黄牌，当天复盘；一个月两次 → 红牌，收回权限报主公
