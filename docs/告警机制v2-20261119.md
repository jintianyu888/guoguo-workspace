# 告警机制 v2（2026-11-19 · 主公令：连续告警要治根，别只治表面）

## 问题
今日 16 条告警里，7 条是同一条「⚠️ OpenClaw 定时任务异常」，内容几乎一样，只差时间戳。
根因不是任务失败次数多，而是**去重粒度错**：原来整批异常算一个指纹，只要异常集合变一下
（某任务在 ok/error 之间跳），整批重推。同一批三条故障一天能推七八次。

## 四处改动

1. **逐条去重（cron-failure-alert.py v2）**
   指纹从「整批」改成「类型+任务ID+失败档位」，逐条记 6 小时。
   只推新增项，持续中的用一行「另有 N 项仍在持续」带过。恢复后再失败会立即重报。

2. **已认领故障（新增 tools/fault-ack.py + state/work/fault-ack.json）**
   明确知道原因、在等修复窗口的故障，登记后不再即时推（默认 72h，可调），
   期间只在夜间汇总里体现。适用场景：修复已提交但验证窗口在几天后的。

3. **修掉两个真实故障**
   - 备份等待守卫 `backup-wait-idle.sh`：提示语用单引号，`$((MAXWAIT/60))` 不展开，
     告警里出现字面量。已改正。
   - T2 中间备份 `tier2-launch.sh`：拉起 systemd 单元时缺 `XDG_RUNTIME_DIR`、没加 `--no-block`，
     cron 会跟着等 90 分钟被判超时（连续失败 4 次就是这么来的）。已补环境变量、
     加 `--no-block`、外层 `timeout 120`，cron 只负责拉起立即返回。

4. **修掉两个超时**
   - 每日用量快照(v2)：21:40 → 21:42，超时 900 → 1800 秒
   - 维护管家-晚间核查：21:40 → 21:45，超时 900 → 1800 秒
   （两个原来撞在同一分钟，模型调用互相抢）

## 顺手修的闸门
`preflight.sh cron` 原来要求「0 重叠」，而全舰队长期有 32 处历史重叠，导致闸门永远红、
天天被绕过 —— 等于没有闸门。改成**基线增量**闸门：记基线文件
`state/work/cron-overlap-baseline.txt`，只拦「比基线更多」的新增重叠。
实测：`放行：重叠 32 处（基线 32，未增加）`。
