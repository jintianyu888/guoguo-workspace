# 模型池使用机制 v1.0（2026-11-21 主公令）

主公原话：「模型池反应太慢、毛病太多，立刻找优化方法、更好的使用机制」。

## 一、问题（实测，不是感觉）

- 换一个管家模型：官方整包 patch 校验全部 39 个管家，实测 **100s**
- 全量换模型：同样 **102s**，而且中途失败没有快回滚
- 余额数字：页脚长期停在旧快照（实测 2 小时前），不同脚本各读一份，数字互相打架（141.49 / 158.6 / 137.38 三个值同时"存在"）
- 页脚新鲜度标签取的是 quotas 的抓取时间，不是余额的时间 → 显示"1 小时前"但看着像实时

## 二、新机制（三件套，全部零 token）

### 1. 一口速查：tools/model-status.py（0.15s）
- 直连 DeepSeek 官方 /user/balance 取余额（约 0.1s），顺手回写 state/model-econ/balances.json
- 直读 openclaw.json 出"管家→模型"分布，不启动 CLI
- 读 state/ledger/jobs.db 出近 24h 任务失败数
- 落盘 state/model/status.json，供页脚与面板读
- 用法：`python3 tools/model-status.py`

### 2. 秒级切换：tools/model-switch.sh
- 单管家：`bash tools/model-switch.sh <agent> <provider/model>` → 实测 **10.8s**（原 100s，9 倍）
- 全量：`bash tools/model-switch.sh --bulk deepseek/deepseek-flash` → 实测 **2.3s**（原 102s，43 倍），带备份+官方校验+失败自动回滚
- 每次切换自动写 model_policy 策略账本与工作日志，回滚命令就是反向切一次

### 3. 15 分钟自动保鲜
- 复用现有 oc-model-sentinel.service，加 ExecStartPre 跑 model-status.py（drop-in: 10-status.conf）
- 余额快照最多 15 分钟旧；页脚直接读实时值，不再读量价抓页的旧字段

## 三、口径（唯一）

- 实时余额只认 `state/model/status.json`（由 model-status.py 写入），其他任何文件里的余额都只作历史
- 页脚必须带刷新时间；超过 45 分钟未更新的余额视为过期（规则 R30 报红）
- 模型策略以 docs/模型使用策略账本-20261101.md 的 2026-11-21 定版为准（R29 机器核查）

## 四、验证命令

```bash
bash tools/model-switch.sh --status      # 同上一行
python3 tools/model-footer.py deepseek/deepseek-flash   # 刷新时间应是刚才
bash tools/r29-model-policy.sh           # PASS

```
