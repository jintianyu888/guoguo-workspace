# 空转找活规则 v0.3（草案待审）

## 要解决的问题
四大管家在没有被派活时静默空转：陈旧任务长期沉淀，新问题无人主动发现，全部压到果果身上。

## 规则

**R1 空转判定**
某管家当日同时满足：(a) 无 in_progress 任务；(b) 无当日交付（文件/报告）→ 判定为空转。

**R2 空转后的固定动作顺序**
1. 先认领陈旧任务（不得跳过直接找新活）
2. 再找新任务
3. 两者都无 → 主动报「无活可做 + 原因」，不得沉默

**R3 陈旧任务三选一**（每条必须给出处置，不许放着）
- 认领：写入 in_progress 并给预计完成时间
- 申请关闭：须附证据（已由他处完成 / 前提消失 / 判断有误）
- 申请转派：须说明为什么不归自己

**R4 新任务发现**
- 只能入 quarantine（待批），不得自派自干
- 每日上限 5 条
- 同一线索 7 天内不重复上报（线索 key 去重）
- 必须写清：发现依据（file:line 或命令输出）、影响、建议动作

**R5 只在半价时段找活（主公 2026-11-01 14:04 令）**
- 高峰（工作日 09:00-12:00、14:00-18:00）**只记录不找活**：空转只登记，不动手
- 找活动作一律排到半价窗：18:00 后、12:00 前、周末与节假日全天
- 当日 13:00 验收只判「谁空转」，把找活任务写进当晚报批单，18:05 半价窗统一执行
- 违反时段找活视为违规，记入台账

## 各管家线索清单（找新任务的方向）
- 维护管家：告警重复、假绿、巡检盲区、文档过期
- 备份管家：盘位水位、演练失败、保留策略异常、回收站堆积
- 模型管家：悬空引用、额度异常、评审池失效、评测缺口
- 干活管家：cron 连败、脚本死链、路径写死、护栏缺失

## 防滥用（硬约束）
- 不自批：新任务入 quarantine，由果果审
- 不重复：线索 key 去重，7 天冷却
- 不越界：硬盘边界、权限分层、删除三重校验一律不变
- 不烧钱：找活优先本地脚本；单日模型调用上限 5 次
- 不假报：无活可做要明说，不许编造任务凑数

## 与现有体系的关系
不新建平行体系，挂到现有三处：
1. 管家日常守则增补 v0.3（行为规则）
2. 台账 quarantine 状态（候选池）
3. 13:00 验收检查（监督闭环）
