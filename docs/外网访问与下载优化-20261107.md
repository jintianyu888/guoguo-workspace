## 三、今天已做的优化（不需要 VPN）
1. pip 全局换阿里云源（extra-index 保留官方兜底）
   ~/.config/pip/pip.conf → index-url=mirrors.aliyun.com/pypi/simple/
   实测下载 requests wheel：3.0s（原先官方源 94KB/s）
   备份：~/.config/pip/pip.conf.bak-20261107
2. HF 镜像写进 ~/.profile（HF_ENDPOINT=hf-mirror、HF_HUB_DISABLE_XET=1），任何脚本默认走镜像
3. ollama 拉不动的问题用「HF 镜像下 GGUF + ollama create」绕过：
   nomic-embed-text 274MB / 32 秒 完成（官方 registry 同款要 27 分钟）
   经验：以后所有 ollama 模型都走这条路，不再等 registry
4. npm 早就在 npmmirror，无需改
5. 新增 tools/net-egress.sh：status / env / test，一键判断出口与代理可用性

## 四、要让 WSL 真正吃到 VPN 的两条路
### A. WSL 镜像网络（彻底，但要重启 WSL）
.wslconfig 加 networkingMode=mirrored → WSL 与 Windows 共享网络栈与 127.0.0.1，
VPN、系统代理自动生效。
代价：wsl --shutdown = 整个 WSL 停（网关、面板、模型全停几十秒），且网卡布局变化
可能影响：已配对的 Windows 节点、docker、绑 127.0.0.1 的服务。
本机 WSL 2.7.14 / Windows build 26300，支持该模式。
→ 属重启级操作，需主公点头 + 走窗口（建议 08:00 重启窗口一起做）。

### B. 只借代理（零风险，但需主公在 Clash 点一下）
Clash 打开「允许局域网连接」→ WSL 可用 http://172.18.240.1:7890 按需走代理：
  source <(tools/net-egress.sh env)
只给单个下载任务用，不影响其它流量；不改任何系统配置。

## 五、建议
先做 B（今天就能用，代价零）；A 不必急，因为大文件下载已有更快的镜像路径，
VPN 的实际增益主要是 docker 镜像、Google 系 API、个别 GitHub raw。
等哪天真需要 docker/境外 API，再在窗口做 A。

## 七、决定（默认策略）
1. 默认直连；能走镜像的一律走镜像（pip→阿里云、npm→npmmirror、HF→hf-mirror）
2. 只有四类强制走代理：raw.githubusercontent、huggingface 原站、docker 镜像仓库、Google 系
3. 落地方式：bash tools/net-egress.sh run <命令> —— 只给那一条命令套代理，不改全局
4. 方案 A（wslconfig 镜像网络）判定不需要，代理已够用；#904 关闭
5. 不做全局 http_proxy：会让阿里云/npmmirror 反而变慢，且影响飞书与内网调用
