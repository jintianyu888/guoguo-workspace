# 每周整机重启 + 开机自愈（2026-11-17 主公定 B 方案）

## 一、为什么这么做

- 每天需要清的是网关进程（RSS 每天涨，57 小时已 8.9G）→ 每天 08:00 只重启网关，2 分钟恢复。
- Windows 侧需要重启的是更新、vhdx 锁、长跑泄漏 → 周级即可，所以放周日 04:00。
- 不做每天整机重启：WSL 靠登录态触发，未开自动登录（AutoAdminLogon 为空），重启会停在登录界面，网关/面板/回调全断到有人登录为止。
- 整机重启后 WSL IP 会变（当前 172.18.242.44），而 5 条 portproxy 写死 IP：18789 / 9443 / 8899 / 18899 / 18888。所以必须有「按新 IP 重写 portproxy」的自愈。

## 二、组件

- **每周日 04:00 `OpenClaw-Weekly-Reboot`**（最高权限、登录态）
  → `C:\Users\J\openclaw-weekly-reboot.ps1`
  → 先调 WSL `tools/reboot-safe-check.sh`：备份锁/镜像/推送/压缩在跑就每 2 分钟重试，最多 40 分钟；仍忙则跳过本周（不硬重启）
  → 安全后 `shutdown /r /f /t 60`
- **登录时 `OpenClaw-Boot-Heal`**（最高权限、登录态）
  → `C:\Users\J\openclaw-boot-heal.ps1`
  → 等 WSL 可用（最多 5 分钟）→ 取 WSL 新 IP → 重写 5 条 portproxy
  → 跑 WSL `tools/boot-recover.sh`：拉起网关/面板(guoguo)/TLS 代理、健康探测、挂载检查、飞书报备
  → Windows 侧再验一次 `http://127.0.0.1:18789/health`
  → 日志 `C:\Users\J\openclaw-boot-heal.log`

## 三、安装（只需一次，需管理员）

双击桌面 **OpenClaw-每周重启-安装.bat** → UAC 点「是」→ 安装器注册两个任务并立刻跑一次 Boot-Heal 自检。

## 四、验收

```powershell
Get-ScheduledTask -TaskName 'OpenClaw-Weekly-Reboot','OpenClaw-Boot-Heal' | Select TaskName,State
Get-ScheduledTaskInfo -TaskName 'OpenClaw-Boot-Heal' | Select LastRunTime,LastTaskResult
```

- 日志：`C:\Users\J\openclaw-boot-heal.log`
- WSL 侧：`state/log/boot-recover.log`
- 飞书会收到「【开机自愈】WSL 已就绪…」一条

## 五、已知限制

- 未开自动登录：周日 04:00 重启后停在登录界面，WSL 不起；你登录后自愈链在 1-3 分钟内把一切拉回。这段时间的 07:15 增量备份、07:40 早间简报等会漏，需要的话可加「漏档补跑」。
- 重启只在备份空闲时执行；备份拖过 40 分钟就跳过本周，不会打断备份。
- portproxy 重写需要管理员：任务用「最高权限」注册，安装时确认一次即可，之后每次开机静默执行。

## 六、回滚

```powershell
Unregister-ScheduledTask -TaskName 'OpenClaw-Weekly-Reboot' -Confirm:$false
Unregister-ScheduledTask -TaskName 'OpenClaw-Boot-Heal' -Confirm:$false
```

删脚本：`C:\Users\J\openclaw-weekly-reboot.ps1`、`openclaw-boot-heal.ps1`、`install-openclaw-reboot.ps1`。
WSL 侧改动可回退：`tools/boot-recover.sh` 备份、`tools/reboot-safe-check.sh` 直接删。
## 七、漏档补跑（2026-11-17 主公令加）

开机自愈第 7.5 步会自动补跑停机期间漏掉的「轻活」：

- 停机时长：优先读重启前打的标记 `C:\Users\J\openclaw-last-reboot.txt`（真实停机时长，含等待登录的几小时）；没有标记则用 WSL uptime 兜底。超过 12 小时按 12 小时算。
- 只补白名单：简报 / 日报 / 报告 / 体检 / 自审 / 汇总 / 审计 / 扫描 / 提醒 / 计划 / 巡检。
- 一律不补：备份 / 镜像 / 推送 / 清理 / 压缩 / 升级 / 重启 / 删除 / 归档 / 演练 / 外发 / 下单付款。
- 串行执行，单次最多 6 个，每个 5 分钟超时；工作日 09-12 / 14-18 高峰不补（避免烧 token），周日不受限。
- 结果写 `state/work/cron-catchup.log` 并推一条飞书「【漏档补跑】补跑成功 N 个…」。

手动用法：

```bash
python3 tools/cron-catchup.py --since-minutes 600 --dry-run   # 只看会补哪些
python3 tools/cron-catchup.py --since-minutes 600            # 真补（最多 6 个）
python3 tools/cron-catchup.py --since-minutes 600 --force    # 高峰时段也补
```

注意：T1 增量备份等重活不补跑，靠备份链自己的补档机制；如果哪天需要补，人工点一次即可。
补跑细节（v1.1）：判定用任务自身 `state.lastRunAtMs`（不信 cron-miss 的 last）；应跑时刻距今 <12 分钟不补（防正在跑）；同一任务 6 小时内被补过就跳过（`state/work/cron-catchup-seen.json`）。实测 21:05 补了 3 个漏档（简报-晚 20:30 未跑、会话体积巡检、假绿扫描），再跑一次候选=0。
## 8. 自动登录（2026-11-17 22:23 实跑通过）

目的：整机重启后不用人登录，WSL / 网关 / 面板自己起来。

现状（已验证）：Win11 账户 GY\J，自动登录开，密码存在 HKLM\Software\Microsoft\Windows NT\CurrentVersion\Winlogon\DefaultPassword（仅管理员可读）；登录后 60 秒由任务 OpenClaw-Lock-After-Logon 自动锁屏。

### 踩过的坑（都真实发生过）
1. ValidateCredentials 在本机抛异常：.NET PrincipalContext(Machine).ValidateCredentials 直接报 An extended error has occurred（PrincipalOperationException），把正确密码判成错。改用 Win32 LogonUser（advapi32，LOGON32_LOGON_INTERACTIVE）后正常；错密码返回 1326。
2. DevicePasswordLessBuildVersion = 2 会让自动登录失效：Win11 免密模式开启时系统只认 Hello/PIN，注册表写了也不生效。必须改成 0（本机已改）。
3. 登录失败后 Windows 自己把 AutoAdminLogon 清回 0：所以事后查到 0 不能断定「没配过」；反过来重启后该值仍为 1 是自动登录成功的旁证。
4. 别被 net user 的「需要密码 = No」误导：它只表示允许空密码，不代表当前没密码。

### 安装器
- 脚本：C:\Users\J\oc-autologon-v14.ps1（v1.4，自提权、LogonUser 校验、三次不过可强制写入）
- 桌面入口：OpenClaw-开启自动登录.bat（指向 v1.4）、OpenClaw-关闭自动登录.bat（回滚）
- 日志：C:\Users\J\openclaw-autologon.log（只记校验结果与核验行，不记密码）

### 验证口径（2026-11-17 22:23 实跑）
四个时间点自洽，不靠人确认：
- Windows LastBootUpTime = 22:23:11
- WSL 起来 = 22:23:31（无人操作）
- 锁屏任务 LastRunTime = 22:24:30（= 登录 + 60s，Result=0）
- boot-heal 22:23:38 → 22:25:01：网关 200、面板 200、portproxy 在位、漏档补跑 0 候选
- AutoAdminLogon 仍为 1（失败会被系统清零）

### 安全说明
密码明文存注册表（管理员可读）。可信环境下可接受；要更严的顺序是：先开 BitLocker，再考虑改用 Sysinternals Autologon（存 LSA secret）。关闭：双击 OpenClaw-关闭自动登录.bat（AutoAdminLogon 置 0 并删掉存留密码）。
