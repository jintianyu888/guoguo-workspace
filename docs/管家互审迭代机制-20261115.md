# 管家互审迭代机制 v1.4（2026-11-15｜已吸收 Hermess 复核 v1：4高/11中/3低）

## 0. 一句话
两份产出是失败态。正确形态：作者起草 → 对家只挑错 → 作者逐条改 → 对家按清单判 → **只留一份定稿**。

## 1. 配对准入（硬条件）
- 配对表（含 agent id 与日常 provider，开工前预校验，同族换替补）：
  - 果果(id=main, deepseek) ↔ Hermess(id=sheet-music, zai)
  - 维护(maint, zai) ↔ 备份(backup, deepseek)
  - 模型(model, kimi-coding) ↔ 干活(work, qianwen-token-plan)
- 双方**日常模型 provider 必须不同**（同厂不同档位不算，同族盲区重合＝自审）
- loop.json 记录 author_model / reviewer_model / provider 是否不同；不满足即换人，轮次无效
- 校验时点：**复核方接单时自检一次 + 发布前重采一次**，两次都要满足异 provider
- 目录：state/review/<作者id>-<复核id>/<发起日YYYY-MM-DD>/（跨日不换目录，时间戳记 loop.json）

## 2. 通道（写死）
一律走 `bash /home/j/.openclaw/workspace/tools/agent-msg.sh send <对家> "<正文>"`，loop.json 记消息文件名+收讫时间。禁止用顺手通道。

## 3. 轮次与时限
- 最多 3 轮；每轮 deadline 限 **4–24h**（由作者给，超出范围视为无效），逾期先宽限一次再判 timeout，逾期 → loop.json 标 timeout，按「复核未完成」处理，可改派
- deadline 逾期后的改派/换人决定人：**果果**，改派需在 loop.json 写新 deadline 与接手人
- 失败轮次（如对家未产出、通道断）**不计入** 3 轮上限

## 4. 意见编号与逐条回执（硬性）
- 复核方每条意见编号 **R{轮}-{序}**（如 R2-H1、R2-M3），必须**引用具体句子/行号/数字**，否则该条无效、作者可不响应
- 作者 draft-vN+1 顶部附「意见处理表」：编号｜已改/部分改/驳回+理由｜落点（节号）
- 高严重度只许「已改」，不许驳回；中/低可驳回须书面理由

## 4b. 产物（唯一）
- 作者：`draft-vN.md`（v2 起顶部附**意见处理表**：R{轮}-{序}｜已改/部分改/驳回+理由｜落点节号）
- 复核方：`review-vN.md`（唯一产物，四段：编号意见｜位置｜问题｜改法｜严重度）
- 定稿：`final.md`（仅合格时生成）
- 全部落盘 state/review/...；文本入 git，大附件只留路径

## 5. 严重度语义（写死）
- 高：不改则不可执行，或涉及数据/权限/资金/重启级风险
- 中：边界缺失、失败分支缺失
- 低：措辞格式
**仍有未清零的高严重度 → 复核方不得写合格；超限发布只能带中/低未修项**

## 6. 合格判据（七项全过，缺一即不合格）
1 目标与适用条件
2 步骤含执行人+环境+时限
3 每条验收判据可判定（命令/数字/文件）
4 失败分支有回滚
5 已知缺陷已列（无人写"无"）+ 责任人
6 发布方式与审批人
7 上轮意见全部关闭（处理表无未回执项；高严重度无驳回）
另加**四问必查**：依赖是否具备｜步骤能否执行｜失败能否恢复｜结论能否验证

## 7. 终态（四种，互斥）
- A 合格发布：六项全过 + 四问无缺口
- B 未通过·带缺陷发布：3 轮未过，仅中/低未修项，须列（编号+严重度+责任人+关闭时间）+ **主公确认**，final 头写「复核结论：不通过（超限第N轮）」
- C 超时失效：标 timeout，改派或换人，重开轮次
- D 弃用：连续 3 天无 final → 该组合停用，转果果人工

## 7b. 判定依据（文件级，人/脚本都可断言）
- 终态A：final.md 含「复核结论：合格」，且与最新 review-vN 一致
- 终态B：final.md 含「不通过（超限第N轮）」+ 未修项清单（编号/严重度/责任人/关闭时间）+ 主公确认记录；**未修项含高严重度即不得走 B**
- 终态C/D：以 loop.json 的 result 字段为准；终态D：最近 closed_at 超 72h
- 每个目录 final.md 有且仅一份

## 7c. loop.json 最小 schema（写入方=作者）
pair｜started_at｜rounds[{n, draft, review, reviewer_model, started_at, deadline, closed_at}]｜result(success|defect|timeout|dead)

## 8. 发布权
- final 默认只落盘 + 内部知会
- **对外推送（群/私聊/外部）单列一步，须主公确认后由指定人执行，回执链接与时间**

## 9. 密级
禁止含明文凭据、密钥、内网 IP、个人信息；作者送审前自查，loop.json 记"已自查"。

## 10. 未审拦截
只有 draft 无 review → 不得生成可发布 final；已生成则文件头写「未审·禁止发布」，任何环节见此即阻断。申诉：作者在 draft-vN 写「异议+理由」，复核方下轮必须逐条回应。

## 11. 触发方式（按需为主）
硬触发三类：①对外发布前 ②删除/权限/资金/重启级操作前 ③每日 12:50 自审各挑一项。其余按需，不搞每日全量空转。
