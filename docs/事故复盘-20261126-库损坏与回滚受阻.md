# 事故复盘-20261126 状态库损坏与回滚受阻

> 记录人：果果｜时间：2026-11-26｜状态：已恢复，版本 2026.11.10 留守观察

## 一、现象
- 08:07 升级 2026.11.9 → 2026.11.10 后，08:07:55 起日志出现 "plugin load reentry detected"
- 派生 AgentDatabaseAdmissionError（company3、security 等）与 "Sessions remain unavailable"
- 08:45 sqlite_wal_sidecar_identity_mismatch FATAL → 网关自杀，之后每次启动 integrity_check 失败 exit 78
- 18:35–18:39 经损坏库重建恢复；全天 23,423 条 reentry 报错

## 二、根因（两层）
1. 直接原因：升级流程直接拉起网关进程（非 systemd 托管），systemd 认为网关未运行 → 看门狗再拉第二个实例 → 两进程同开一个 state 库，第二实例重建 -wal（inode 465762 vs 1334327）→ 11.10 新增 WAL 身份校验判定非法 → FATAL 终止且跳过清理 → 库页损坏。
2. 诱因：11.10 的 plugin 准入缺陷（reentry）让 health 抖动，看门狗更早介入。

## 三、处置
- 18:39 用损坏库内数据重建 openclaw.sqlite（113 表、217 会话、99,022 审计事件），损坏原件留存 openclaw.sqlite.corrupt-20261126T1840
- 新增护栏：gw-start-guard.sh（端口占用拒绝二启）、db-integrity-gate.sh（升级后验三库，坏即回滚）、每日 03:30 三库巡检、R42 规则、oc-reentry-watch.timer（30 分钟盯 reentry）

## 四、二次事故：回滚失败（19:27–20:09，网关中断 40 分钟）
- 19:27 执行 tools/rollback-1110.sh 装 11.9，19:30 起 11.9 拒绝启动：
  "Refusing to start ... binary (2026.11.9) is older than the config last written by OpenClaw 2026.11.10"
- 根因：11.10 写入了 openclaw.json 的 meta.lastTouchedVersion=2026.11.10，官方降级保护；我的回滚脚本未处理这一层
- 20:04–20:08 一轮强制重装把 11.10 装回，20:09 网关恢复
- 教训：任何回滚/降级必须先改版本戳（tools/stamp-config-version.py）+ 放行 OPENCLAW_ALLOW_OLDER_BINARY_DESTRUCTIVE_ACTIONS=1；官方建议"降级须连同升级前配置/库备份一起还原"
- 修正：upgrade-openclaw.sh 与 upgrade-panel.sh 的自动回滚分支已加版本戳改写（否则将来自动回滚同样会把网关留在宕机态）；新增 R43 机器检查

## 五、当前结论
- 11.10 留守观察（主公 2026-11-26 20:19 决定：不降级，等新版本）
- 11.10 已进 state/work/upgrade-deny.json 禁用名单，升级判定不会重复挂载该版本；新版本出来先验 reentry 再放行
- 20:09 之后 reentry=0、Sessions unavailable=0，趋势记 state/work/reentry-trend.jsonl

## 六、复盘要点
- 自证不可靠：多次"升级成功"判定只看版本号与 health 200
- 危险动作前置闸门要覆盖"降级"，不能只覆盖"升级"
- 回滚路径此前从未真实演练，第一次跑就翻车；今后每次升级前先 dry-run 回滚路径
