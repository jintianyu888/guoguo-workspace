# 升级规则（唯一真源）· 2026-11-21 主公令

> 此前规则散在 docs/OpenClaw升级节奏与策略-20261115.md、docs/升级执行-20261124.md、tools/upgrade-auto.sh 注释里，本次合并为一份。冲突时以本文为准。

## 一、总原则
1. **升级是「主公决定 + 我执行」，不是系统自决。** 自动流程只能出提案，不能自己装。
2. 任何升级必须可回滚、可验收、有账。
3. 出问题先回滚再排查，不在坏版本上打补丁。

## 二、什么时候允许升
- 目标版本发布满 **7 天**（成熟度门禁，SOAK_DAYS=7），不满一律拒绝；--force 仅限安全修复且需主公同意
- 不进 beta / rc，只走正式版
- 每个特性线只升一次，装完即冻结该线
- 同一时间只保留一条升级线，不做跨线跳跃

## 三、流程（每天 07:30 判定 → 08:00 窗口执行）
1. 07:30 `tools/upgrade-auto.sh`（**只判定、只出提案**）
   - 合规 → 写 `state/work/.upgrade-proposal.json` + 飞书推送「【升级待批】当前 → 目标（已发布 N 天）」
   - 不合规 → 记日志退出，不打扰
   - **绝不写 .upgrade-armed**
2. 主公回复「批准升级 <版本>」→ 我写两个件：
   - `state/work/.upgrade-approved`：{"target":"2026.11.6","approved_by":"金鱼","at":"2026-11-21 10:30"}
   - `state/work/.upgrade-armed`：目标版本一行
   两件必须同时存在且版本一致，缺一即拦截。
3. 08:00 `tools/restart-window.sh`
   - 自检不全绿 / 备份在跑 / 红区 → 不升不重启，推送原因
   - 有挂载无批准件 → **拦截**，只做常规重启，推送「【升级拦截】」
   - 双件齐全 → 执行 `upgrade-openclaw.sh`（备份 + 四库快照 → 安装 → 重启 → 版本验收 → 13 项自检 → 失败自动回滚）
4. 升完写 `state/work/.upgrade-auto-done`，同日不再重复升级

## 四、熔断
- 升级后 13 项自检任一 FAIL → 立即回滚；回滚失败 → 停手告警，等人
- 5 分钟内重启超过 1 次 → 停手告警，不再自动拉起
- 窗口内任何异常，优先保证「能回到旧版本」

## 五、机器校验
- 规则 R17：`python3 tools/upgrade-policy-check.py`
  - 检查 upgrade-auto 不再自动写挂载件
  - 检查有挂载必有匹配批准件
- 每天开工闸门自动跑，违规落 `state/work/rule-violations.jsonl`

## 七、升级选项由主公决定（2026-11-21 11:36 主公令）

- **决策权归主公**：任何版本升级都必须由主公明确说「批准升级 <版本>」，果果只提案、不代决。
- **面板显示发布天数**：果果助手右上角信息条显示 `OC 当前版本 → 最新版本 · 发布 N 天`，并标注「已满 7 天，可升级」或「未满 7 天，建议再等」。
  - 数据源：`state/work/upgrade-info.json`（`tools/upgrade-info.sh` 生成，零 token）
  - 刷新：`oc-upgrade-info.timer` 每 6 小时（00:10/06:10/12:10/18:10）
  - 接口：面板 `GET /api/upgrade`
- 07:30 的判定任务只负责「算出天数并提一句」，不再写挂载文件、不再自动执行。
- 批准后的执行仍是：写 `state/work/.upgrade-approved` + `.upgrade-armed` → 08:00 窗口执行 → 13 项自检 → 失败自动回滚。
