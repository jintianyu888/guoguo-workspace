# 错误噪声与计划内窗口规则（v1.0 · 2026-11-14 主公令）

> 主公原话：正常的就该是正常的，错误的就该是错误，不要把正常的报成错误，那真正的错误就被掩盖了。

## 一、原则
1. **不屏蔽，只分类**：计划内噪声单独计数，绝不从统计里消失；报告里始终并列显示「总数 / 计划内 / 真错误」。
2. **计划内要有依据**：只有能说出「这个时间段本来就会断/会重连/会重启」的才算计划内。
3. **永不豁免**：`ENOSPC`、`SQLITE_FULL`、认证失败、密钥无效、OOM 五类即使落在窗口内也一律算真错误（`never_noise` 优先于窗口判定）。

## 二、实现
- 配置文件：`state/expected-noise.json`（唯一真源，改这里即可，不用改代码）
  - `windows`：时间窗 + 原因，现含 01:00–02:30 全量备份、04:00–06:05 静默/断网窗、08:00–08:20 重启窗、21:30–21:50 议员审计突发
  - `always_signatures`：与时间无关的已知噪声（axios 超时、DNS 解析失败、飞书流式卡片降级、Code Mode 沙箱路径拒绝等）
  - `never_noise`：永久算真错误的签名
- 执行：`tools/nightly-error-audit.py`（零 token，夜间跑）
  - 分类：`never_noise` 命中 → 真错误；`always_signatures` 命中 → 计划内；否则按时间窗判定
  - 报告口径：`近 N 小时共 X 条；计划内 Y 条；新/需处理 Z 条 / K 类`
- 归一化：UUID、长十六进制、时间戳、URL、open_id、appId、各种 id= 值统一替换，避免同一问题被拆成上百类；堆栈续行（`at ...`、`_timeout:`、`error: [Object]`）非独立错误，已过滤。

## 三、调参纪律
- 新增签名必须写清「为什么它是计划内」，并在当日报备。
- 任何签名如果一天内吞掉超过总量 30%，次日审计必须复核，防止把真问题洗成噪声。
- 新出现的错误类默认算真错误，直到有人给出计划内依据。

## 四、当前实测（2026-11-14 09:39，近 24h）

## 五、回滚
- 删除 `state/expected-noise.json` 即回到旧口径（仅内置签名 + 04–06 窗口）。
- 代码改动前的版本在 `state/backup/` 下。
