# 五大管家日报（2026-11-14 主公令）

## 要求
主公每天早上看到五家：昨天完成了什么、今天计划做什么，以确认他们还活着、还在进步。

## 落地方式（零 token）
- 脚本：\`tools/butler-daily-report.py\`（默认打印，\`--send\` 走 \`tools/notify.sh\` 推主公飞书）
- 定时：\`oc-butler-report.timer\` 每日 07:00 CST（\`oc-butler-report.service\`，oneshot）
- 校验：\`systemctl --user list-timers oc-butler-report.timer\`；手工试跑 \`systemctl --user start oc-butler-report.service\`

## 数据来源（全部为既有事实，不含推测）
- 各家 \`state/self-review/<昨天>.md\` 是否存在及字节数（昨天有没有真产出）
- 各家定时任务昨日实际运行记录（\`openclaw cron list --json\` 的 lastRunAtMs/lastStatus）
- 任务账本 \`state/tasks/tasks.db\`（昨日关单数、在办项）
- 今日计划：任务 \`state.nextRunAtMs\` 落在今天的定时任务（不是简单解析 cron 表达式）

## 判据
- 自审缺失 → 日报第三节点名；连续两天缺失 → 升级处理（与 13:35 守卫 \`oc-butler-audit-guard.timer\` 互补：守卫在白天抓当天，日报在早上复盘昨天）
- cron 数据取不到时降级用缓存 \`state/work/cron-cache.json\` 并在末行标注来源

## 坑
- \`agentId\` 与展示名不一致：Hermess 的任务属于 \`sheet-music\`，必须按 id 集合匹配，不能按名字。
- 只看 cron 的 \`lastStatus=ok\` 会假绿：必须同时核 \`state/self-review/\` 文件是否落盘。
- \`openclaw cron list --json\` 约 15 秒、峰值 1G 内存，放在 07:00 单次执行，不要高频调用。
