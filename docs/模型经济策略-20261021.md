## 一、先纠正一个旧认知（重要）
DeepSeek **不是「夜间 00:30-08:30 折扣」**，而是**峰谷两档**：
- **高峰**：周一至周五 9:00-12:00、14:00-18:00（法定节假日除外）
- **空闲**：其余全部时段（含夜间、周末、全天节假日）= 高峰价的 **50%**

→ 推论：**周末全天都是半价**，重活排周末比排夜间更划算（夜间还要睡觉不被打扰）。

## 三、五档分工（核心）

### L0 本地 30b — 零成本，不占云端限流
适用：定时巡检、日志判断、格式转换、早报汇总、简单布尔判断。
原则：**能写脚本的绝不调模型**；必须调模型的判断类任务走本地。

### L1 deepseek-flash — 日常主力
适用：对话、写代码、文档处理、工具调用、快速查询。
理由：价格最低的云端档（输入 1 元/百万），工具调用稳定，响应 4-5 秒。
注意：**高峰正价、闲时半价**，因此高峰轻活优先本地或订阅制。

### L2 订阅制打满（GLM Coding Plan / MiniMax M Plan）
适用：**量大、不着急、不需要极致质量**的活——批量改写、长文本摘要、多轮迭代、素材整理。
关键动作：
- GLM 每周 10000 分，**周四查一次消耗**，剩余额度灌批量任务，周不清零就是白扔钱
- MiniMax ¥49/600M tokens，**每百万仅 ¥0.08**，是全场最便宜的通道，适合无脑大批量
- 订阅制有并发/限流（429/1305），**不要用来跑关键路径**，只做后台批量

### L3 deepseek-v4-pro — 硬活单发
适用：硬调试、架构设计、长文档精读、复杂推理。
时点：**周末或夜间（5 折）**，13.5 元/百万输出 vs 27 元，差一倍。
纪律：**不做算术**，数字一律交给脚本（历史两次算错同一题）。

### L4 交叉审核（双审）— 固定组合 + 轮换第二意见
组合：**deepseek-v4-pro（一审）+ 第二意见轮换（glm-5.3 ↔ kimi-k3）**
理由：两个不同厂商 = 不同训练数据 = 真正的独立性；同一家两个模型容易同错。
轮换意义：glm 长提示易返 0 字节，kimi 长文降智，**换着用可互相兜底**。
铁律：必须报「哪些模型真跑完、各回多少字」，超时/空输出＝没跑完，重跑后才下结论。

### L5 三审 — 只在难题/不可逆时
适用：删数据、迁移、密钥、重大升级、税务/理财/健康关键判断、大额开销。
第三人选：**qwen3.8-max**（12/36，质量高）或 MiniMax M3.1（便宜，适合凑第三个视角）。
成本：三审约等于 flash 的 8-10 倍单次成本，**只在不可逆场景用**。

## 五、token 物尽其用（省钱 4 条）

1. **缓存命中是最大杠杆**：DeepSeek 缓存 0.02 vs 未命中 1.0 = **50 倍差价**。保持系统提示/前缀稳定，别每次改开头。
2. **输出比输入贵 4 倍**：让模型「只给结论、不复述问题」，比省输入更有效。
3. **长上下文是最后手段**：v4-pro 长文价翻倍，先摘要再问，别把 20 万字原文直接塞。
4. **订阅额度不清零但要打满**：GLM 周额度、MiniMax 600M 都是**过期作废**，剩着就是浪费。

## 六、一句话总结
**巡检给本地，日常给 flash，批量灌订阅，硬活压闲时 v4-pro，审核必跨厂商。**

### 关键结论：没有「统一最便宜」，按调用形态选

1. **长会话/长文档反复引用 → deepseek-flash**
   缓存 0.02 是全场最低，GLM-5.3-Flash 的 0.23 是它 **11.5 倍**。同前缀反复问，flash 完胜。
2. **一次性短输入长输出（写作/翻译/代码生成）→ GLM-5.3-Flash**
   输入 0.8、输出 2.8，比 flash 便宜 20–30%，且 1M 上下文。缓存贵无所谓，因为只读一次。
3. **低价值大量判断 → GLM-4.7-Flash（免费）**
   200K 上下文零成本，可直接替代本地 30b 的部分巡检，省 GPU 也省电。
4. **MiniMax 按量没有优势**（≈1.07× flash），**只有订阅 M Plan（¥49/600M ≈ ¥0.08/M）才划算**。
5. **kimi-k3 贵得离谱**（输入 20、输出 100），只配当第二意见，**绝不做日常**。
