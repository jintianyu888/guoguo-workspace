# 升级流程修复记录 2026-11-09

## 背景
2026.11.1 → 2026.11.2 升级连续失败 3 次，每次 rc=5 后自动回滚。表面看像"崩溃"，实为升级流程自锁 + 会话被切断。

## 两个自锁
1. **标记自锁**：upgrade-panel.sh 写 `state/work/.upgrade-running`，随后调 `restart-gateway.sh`；而后者首条守卫就是「发现该标记 → REFUSE exit 5」。
   修法：新增窄口径旁路 `ALLOW_UPGRADE_RESTART=1`，仅升级流程传参，其它调用照旧被拦（`tools/restart-gateway.sh` 第 9-16 行）。
2. **时序自锁（真凶）**：升级第 3 步已 stop 网关，第 5 步却走异步 systemd 重启链路，最终返回 rc=5。
   修法：第 5 步直接 `systemctl --user start openclaw-gateway.service`，沿用原有 60 次 health 轮询 + 失败自动回滚（`tools/upgrade-panel.sh` 第 111-125 行）。

## 新增两项保护
- `tools/post-upgrade-check.sh`：升级后兼容自检——配置可解析 / 插件数 / cron 启用数 / agent 数 / 网关 health / 模型链 / 面板；结果落 `state/work/post-upgrade-<ts>.md`，FAIL 才告警。
- `tools/version-reconcile.sh` + `oc-version-reconcile.timer`（每 6 小时）：比对 A 机与各 paired node 的版本，漂移即落账本（`tools/version-drift-task.py`）+ 当日一次告警，避免"B 机升级靠 agent 回合、被打断就静默丢失"。
