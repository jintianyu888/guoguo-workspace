# 总流程框架（2026-11-01 整合版）

> 把此前分散的六套流程并成一条主线：问题进 → 分级 → 送审 → 执行 → 验收 → 归档。
> 单一真源：本文负责"流程怎么串"；分级细则见 docs/问题分级与审级-单一真源-20261101.md。

## 一、主线六层

**第一层 输入（问题从哪来）**
1. 主公指令（飞书）
2. 告警（state/alerts/alerts.jsonl，notify.sh）
3. 巡检发现（stability-check / 管家自报）
4. 空转找活（idle-scout，仅半价窗）

**第二层 分级（tools/tier-gate.py）**
输出档位 P0 / L3 / L2 / L1 / L0，同时输出：审几审、要什么证据、谁能批、回滚要求。
判级只认结构化标记，不靠关键词猜测。

**第三层 送审**
- P0 → 报主公，0 审，等答复
- L3 → 三审并行（3 家不同厂商，任一否决即停）
- L2 → 双审（不一致加第三审，3 取 2）
- L1 → 自审，写回滚点
- L0 → 直接做

送审工具：tools/cross-review.sh；有效判据 rc=0 + ≥200 字节 + 无错误文本。
L2/L3 送审前先跑 tools/review-dimensions.sh --change "<改动>" 落三问（30天反噬 / 服务目标 / 沉没成本）到 state/review/dim-<date>.md；任何一问答不出即退回补方案，不进双审。
**规则全文必须内联进提示词**（评审员无文件系统权限，今天踩过）。

**第四层 执行**
- 时段：高峰（工作日 09-12/14-18）只做紧急与打印；其余排半价窗
- 长任务：systemd-run 托管，不甩 nohup
- 重启：只走 tools/restart-gateway.sh，08:00 窗内
- 重 IO/大遍历：独立单元 + Nice=19 + IOSchedulingClass=idle

**第五层 验收（tools/steward-acceptance.py）**
- 只认三类产出：状态变更记录 / 经批的新线索 / 处置申请
- 文件堆数量不算交付
- 有 verify_cmd 的任务必须跑通 rc=0

**第六层 归档**
- 台账 state/ledger/ledger.db（唯一真源，写入门槛 L0 直写 / L1 复审 / L2 复审+主公确认）
- 交叉验证台账 docs/交叉验证台账.md
- 教训台账 docs/教训台账-20261101.md
