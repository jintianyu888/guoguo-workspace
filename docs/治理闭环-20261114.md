# 治理闭环与交叉验收（v1.0 · 2026-11-14 主公令后立）

> 主公原话：不要让自己审自己；产出了事情没有落地，落地了没有人审查，这些都要落到机制上。

## 一、三条铁律
1. **不自己审自己**：任何人（含果果、含五大管家）不得担任自己产出的验收人。
2. **产出必须有主**：任何产出（建议、报告、改动、方案）必须带「负责人 + 截止时间 + 验收口径」三项；缺任一项即视为草稿，48 小时内无人认领自动归档作废。
3. **关单必须异人验收**：任务置 done 前，`verify` 字段必须写验收方法与结果，`closed_by` 不得等于 `who`。

## 二、议员审计（第三方视角）
- 定时器：`oc-senate-audit.timer`，每日 21:40（当天活干完后、20:30 简报之前）。
- 轮值表：`state/senate/rotation.json`（索引 0=周日 … 6=周六）。默认周日=本地席、周六=随机、其余按家族轮值。**改表须主公批准；运行时不得指定议员。**
- 席位池（按模型家族去重）：GLM `zai/glm-5.3`、Kimi `kimi-coding/kimi-for-coding`、千问 `qianwen-token-plan/qwen3.8-max`、MiniMax `minimax/MiniMax-M3`、本地 `ollama/gpt-oss:20b`。
- 输入：`tools/senate-pack.py` 生成的原始证据包（近 24h 工作日志、未结任务、提案台账、重启日志、失败单元、告警、五大管家自审原文、定时任务投递状态、闭环缺口扫描），**不含果果的自评文字**。
- 输出：`state/work/senate-audit/YYYY-MM-DD.md`，固定结构（结论/发现 P0-P3/盲点≥2/需主公拍板）。
- 失败处理：主议员失败自动降级到 fallback 席重试一次；仍失败记 `NO REPORT` 并留痕，不静默。

## 三、五大管家的交叉监督
- 每个管家仍做每日自审（自己领域的第一视角）。
- **自审不再是唯一依据**：其自审原文进入议员证据包，由外部模型逐条检查「有没有证据、有没有落地、是不是自己给自己打分」。
- 现阶段不安排管家互审管家（备份/维护等管家执行权限受限，读不到对方工作区，硬做等于造假）；等权限模型允许时再开。
- 果果对管家的验收仍按 13:00 汇总执行，但**果果不得给自己验收**，果果自身的改动一律走议员审计或主公。

## 四、闭环与时限
- 产出 48 小时无人认领 → 归档作废，写进次日审计包。
- P0/P1 发现：当天修或当天书面驳回（写明理由与证据），否则计入未结。
- P2/P3：进周审（周四 19:00 台账周审计一并处理）。
- **7 天未处理自动升级主公**，不许烂在台账。
- 每周统计三项指标：落地率（认领/产出）、验收率（有 verify/已关单）、自闭环占比（closed_by==who/已关单，越低越好）。

## 五、工具
- `tools/senate-pack.py`：证据包生成（只读、零 token）。
- `tools/senate-audit.sh`：轮值取席 + 调模型 + 落报告 + 失败降级。
- `tools/closure-scan.py`：扫 `done` 但无 `verify`、`closed_by==who`、提案长期 new/approved 无 note（只读、零 token）。
- `state/senate/audit.log`：每次审计的席位、模型、结果、耗时。

## 六、边界
- 议员只读：不改文件、不重启、不对外发送、不碰生产。给写权限等于把监督变成第二个执行者。
- 议员不参与决策投票（投票是议会的事）；它的产出是「发现」，不是「裁决」。
- 主公对任何审计结论有最终否决权。
