# 互审协议 v2.0（2026-11-15 17:05 主公纠正后重写）

## 一、主公要的到底是什么
不是"你出一份报告、他出一份审查意见"，而是**两个人合出一份能执行的合格报告**：
1. A 先写方案/报告（草稿 v1）
2. 把**草稿本身**发给 B，B 只做一件事：挑毛病（可行性、漏洞、能不能执行），**不许另写报告**
3. A 按 B 的意见改，出 v2，再发回给 B
4. B 复核，够了就说"合格"，不够继续挑
5. **只有 B 说合格之后，才允许对外发布这一份报告**

产出物永远是**一份**，署名 A，附 B 的签字（复核人）。两份报告并列 = 机制失败。

## 二、角色与硬规则
- 作者（Author）：对被审对象最了解的一方，负责写和改
- 复核（Reviewer）：只挑错、给可执行修改建议，不接管写作
- 硬规则：
  1. Reviewer 的输出只能是"问题+改法"，不接受"我建议重写一份"
  2. 每轮必须给**具体到行/到数字**的意见，空话打回
  3. 轮次上限 3 轮；3 轮仍不合格 → 降级为"带缺陷发布"，把未解决项写在报告末尾"已知缺陷"
  4. 只有 Reviewer 明确写出"合格"二字，作者才能发布
  5. 发布件必须带：作者、复核人、轮次、复核结论、已知缺陷

## 三、落地形态（机器可查）
目录：`state/review/<pair>/<date>/`
- `draft-v1.md` 作者初稿
- `review-v1.md` 复核意见（格式：问题/位置/改法/严重度）
- `draft-v2.md` 修订稿
- `review-v2.md`
- `final.md` 定稿（含签字段）
- `loop.json` 轮次、结论、时间戳

判据（自动可查）：
- `final.md` 存在且含 "复核结论：合格" → 合格
- 只有 draft 没有 review → 未审，不许发布
- final 存在但轮次 > 3 且无"已知缺陷"段 → 违规

## 四、配对
- 果果 ↔ Hermess（默认：果果写系统类方案，Hermess 复核；Hermess 写文档类，果果复核）
- 维护 ↔ 备份
- 模型 ↔ 干活
（模型分工不变：复核人用的模型必须与被审内容的日常模型不同）

## 五、失败的判据
- 出现两份并列报告 → 机制失败
- 复核意见里出现"建议你出一个报告给我" → 打回
- 连续 3 天走不完一轮 → 该对互审停用，改为果果单点审核并记录原因
