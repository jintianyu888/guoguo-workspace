# 空转找活规则 v0.4（双审定稿 · 2026-11-01）

> 双审：kimi-k3.1-pro（2420B）与 zai/glm-5.3（4014B）均判 **GO-WITH-FIXES**，两家结论一致。
> 已按两家共同要求收窄：先只读扫描+上报，运行 1-2 周后再议自动认领。

## 阶段划分
- **一期（现在起）**：只读扫描 + 上报 + 果果统一派单。管家不得自行改任务状态。
- **二期（1-2 周后，看有效率）**：仅对「已批准的低风险任务」开放自动认领。

## R1 空转判定（收紧版，采纳 zhipu FIX-1）
当日同时满足即为空转：
1. 无本人名下 `in_progress` 任务
2. 无以下三类有效产出之一：
   - (a) 认领并推进的任务状态变更记录
   - (b) 经果果审批通过的 quarantine 新线索
   - (c) 处置动作（关闭申请 / 转派申请本身）
3. 文件、报告、"我读了几份文档"这类**凑数产出不计入**

## R2 动作（简化为两步，采纳两家建议）
1. **陈旧任务逐条销账**：对台账中每条超 7 天的 pending/open 任务，输出一行结构化记录
   `{task_id, 动作: 认领|申请关闭|申请转派, 证据}`，**条数必须 ≥ 陈旧任务总数**
2. 销完仍无活 → 报「无活可做 + 原因」

砍掉原四方向线索清单（两家都认为不可验证且会引导凑数）。

## R3 处置口径
- 认领：仅限「已批准 + 批准人非自己 + 本域 + 低风险 + 不含删除/提权/跨工作区」
- 申请关闭：须附证据（已由他处完成 / 前提消失 / 判断有误）
- 申请转派：须说明归属理由
- **quarantine 任务只能由果果审批转出**，管家不得自行转正

## R4 新线索（采纳 kimi 第 3 条）
- 线索 key 固定为「管家 + 规则ID + 规范化对象」，与所有未关闭任务及候选去重
- 问题未解决不得因 7 天冷却到期重新上报
- 证据必须能被只读校验器复核（重跑白名单命令，或核验文件哈希+对应行内容）
- 每管家**未决候选 ≥3 条即暂停新增**
- 新线索一律入 quarantine，不得自派自干

## R5 时段（主公 2026-11-01 14:04 令）
- 高峰（工作日 09:00-12:00、14:00-18:00）**只记录不找活**
- 找活一律排半价窗：18:00 后、12:00 前、周末与节假日全天
- 13:00 验收只判「谁空转」，找活任务入当晚报批单，18:05 统一执行
- 违规时段找活记入台账

## R6 防「假忙」（采纳 kimi 第 2 条）
- in_progress 必须绑定 lease/心跳，超时自动释放并记异常
- 只改状态、只填 ETA 不算交付；**认领后无进展仍判空转**
- 交付只认：13:00 验收器独立运行预登记验收命令且 rc=0，并登记产物路径与哈希
- 一期先靠「处置记录条数 + 状态变更」判定，lease/心跳列二期

## 复用现有体系（两款都强调）
不新建 cron、不新建看板：挂到 13:00 管家交付验收 + 台账 quarantine + 管家守则 v0.3。
