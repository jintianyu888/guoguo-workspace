- **C-12 备份 cron 报「失败」（T1重点备份 error）**｜🟢｜**根因（2026-10-02 21:0x 查获）**：`backup-wait-idle.sh` 里 `busy=$(pgrep -x rsync -c ... || echo 0)` —— **`pgrep -c` 无匹配时会「先打印 0、再返回非零」**，`|| echo 0` 于是又追加一个 `0` → 变量成两行「0」→ `$(( ))` 报 `Illegal number` → **脚本 exit 2 → cron 记 error**（**备份本身已成功**）。**修**：直接用 `-c` 输出、空则补 0（`b=$(pgrep -xc rsync); b=${b:-0}`）。**自证**：`bash -n`/`sh -n` 通过 ｜ 守卫 rc=0 ｜ T1 全脚本 rc=0 ｜ 21:05 归档 19M ✅ 已推群晖 ｜ **自动化状态 error → ok**。

## IO 卡死专项（2026-10-02 全面分析）

### 一句话结论
本机 I/O 卡死**不是单一原因**，是三条主线叠加：
1. **内存盘 / 内存压力**（/tmp=RAM、swap 抖动）
2. **WSL 跨 VM 磁盘桥**（drvfs/9p，本机 6 个挂载 c/d/e/f/g/h）
3. **无超时的网络 / 长任务**（ssh/scp/rsync/tar/dd 挂死 → D 状态）

当前**均已设防**，另补一个 I/O 哨兵（IO-09）。

- **IO-01 /tmp(tmpfs) 打满 → disk full**｜🟢｜实锤 09-29 填 9.8G → SQLite 崩。下载改道 `state/dl/`；`tmp-watch.sh` >80% 警告 / >92% 紧急并清自建大件。
- **IO-02 内存压力 → swap 抖动 → I/O 卡死**｜🟢｜实锤 Swap 77%、网关 7.3G/12G。`vm.swappiness=10`、`vfs_cache_pressure=50`、swap 12G、LCM 压缩、网关自愈。
- **IO-03 WSL drvfs(9p) 跨 VM I/O 挂起【最隐蔽】**｜🟢｜实测 drvfs 写 214MB/s vs 原生 807MB/s（慢 4×），同步无超时。热路径一律留原生 ext4；备份写 /mnt/d 排闲时。
- **IO-04 ext4.vhdx 只增不减 → C 盘满**｜🟢｜实锤 C: 85% → 迁 `D:\WSL`（Plan B）；备份输出改 /mnt/d。
- **IO-05 NAS 传输无超时 → 永久挂起**｜🟡｜BatchMode ssh；关键脚本持续补 `timeout`。
- **IO-06 SQLite 锁 / 磁盘满**｜🟢｜单文件 `flock` + 磁盘水位告警。
- **IO-07 无超时子进程 → 僵尸 / D 堆积**｜🟢｜`proc-watch.sh`（*/30，只在出现/解除各报一次）。
- **IO-08 下载中断 / 卡住**｜🟢｜`dl-fast.sh v2` + 看门狗（见 L-01/L-02）。
- **IO-09 缺 I/O 压力哨兵**｜🟢｜新增 `tools/io-watch.sh`：PSI io + D 状态 + swap + /tmp + 根盘水位 + drvfs 延迟探针；注册「IO体检」定时任务 `*/30`。
