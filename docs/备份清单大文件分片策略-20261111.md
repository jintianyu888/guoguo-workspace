# 备份清单大文件分片策略（账本 #978 · 2026-11-11）

## 问题
/mnt/h、/mnt/e 上每日新增 60-120GB 备份归档，所在 9p/drvfs 挂载全量 SHA-256 一个 110GB 文件实测约 2 小时，
而 tools/manifest-nightly.sh 每盘上限 30 分钟（全局 60 分钟）→ 大归档只能「超时跳过」，清单长期缺项且 rc=0 静默通过。
2026-11-10 实测：/mnt/h 12 个 tar.gz 只有 5 条清单记录。

## 方案（tools/backup-manifest.py）
- 阈值 PARTIAL_MIN_BYTES = 15GiB（CLI --partial-over-gb 可调）：≥阈值的文件不尝试全量哈希，
  改算分片指纹 = sha256("size=N;chunk=C;method=sampled-v2;" + 头段 + 中段 + 尾段各 64MB 的 sha256)，秒级完成。
- 记录字段：
  - 全量：{"name","size","sha256","hash_method":"full-sha256","mtime"}
  - 分片：{"name","size","sha256":null,"partial":true,"partial_sha256","hash_method":"sampled-v2","hash_scope":"head+mid+tail","chunk_bytes":67108864,"mtime"}
- 语义：**partial 不是完整性校验**，只证明大小/时间与头中尾内容一致；下游不得把 partial 当全量哈希用。
- 复用：size+mtime 未变，且（全量 sha 64hex）或（partial_sha256 64hex 且 hash_method/chunk 相同）直接复用；partial 不会被降级成 full。
- fail-closed（双审要求）：读失败 rc=3；超时跳过 rc=4 —— 清单缺项不再静默成功。
- sha256_span 用 dd bs=1M skip=<字节> count=<字节> iflag=skip_bytes,count_bytes 精确跳读，避开 9p 顺序读 ENOMEM；失败回退 python seek。

## 验证
- bash tools/backup-manifest-selftest.sh → SELFTEST PASS（7 项：阈值走 partial / 小文件全量且与 sha256sum 一致 / partial 指纹可独立复现 / 二次运行全复用 / 尾部变化指纹更新 / 默认阈值行为不变 / 记录字段校验）
- 实跑 /mnt/h：12 条记录（7 条 partial），新算 0、复用 5、跳过 0、读失败 0、rc=0，用时 <1 分钟（原来 30 分钟只出 5 条）。
