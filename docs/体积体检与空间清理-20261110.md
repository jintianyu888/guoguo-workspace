# 体积体检与空间清理（2026-11-10 立）

主公 2026-11-10 18:08 令：每次做 OC 系统体检，必须把「系统体积 / 文件扫描」算进去，提前发现该清的、该压的。
本文件是这一项的规则源，改阈值先改这里。

## 一、体检脚本
- 工具：`tools/space-audit.py`（零 token，只读，不删任何文件，约 1.5 秒）
- 产物：`state/disk/latest.json`（本次全量）、`state/disk/history.jsonl`（趋势，每次追加一行）
- 用法：`python3 tools/space-audit.py`（完整）、`--line`（一行摘要，给简报用）

## 二、测什么
1. 六处水位：WSL 根 / D / E / H / X / NAS —— 总量、已用、可用、百分比
2. WSL 镜像膨胀：vhdx 逻辑大小、实际占盘、客户机实占、膨胀比、可压缩量
3. 保留回收站：各盘 `_trash` / `_trash-*` 的总量、批次数、最老批次日期
4. 残包：`*.part` / `*.bad*` / `.crdownload` / `*.tmp`（`.bad` 一律计入，其余 >24h 才计）
5. 归档份数 vs 保留策略（X=2 / E=7 / H=7 / D=1 / NAS 不计）
6. 大文件 Top10（>15G）
7. 趋势：与上次快照比各盘增量，落 `history.jsonl`（可算 7 日/30 日增长速率）

## 三、判定线（越线即进简报）
- P0：任一本地盘水位 ≥ 90%
- P1：任一本地盘 ≥ 85%；保留回收站合计 ≥ 100G；残包 ≥ 10G；镜像膨胀 ≥ 125%
- P2：水位 ≥ 80%；回收站 ≥ 30G；残包 ≥ 2G；镜像膨胀 ≥ 118%；归档超保留份数
- 不推送：NAS 水位（备份目的地，单独由备份线管）

## 四、挂在哪里（不新增 cron，配额已满）
1. `tools/daily-briefing.py` 晚间段（20:30 简报）—— 一行「▍体积」
2. `tools/disk-cleanup-all.sh` 尾部（每日 03:47 四盘清理后）—— 记录趋势 + 落 latest.json
3. 手动：任何时候 `python3 tools/space-audit.py`

## 五、清理的边界（重要）
- 体检脚本**只量不清**。真正删除仍然只走 `tools/disk-cleanup-all.sh` 的白名单（`state/work/cleanup-targets.conf`）。
- 已知缺口：白名单只覆盖 `openclaw-trash`（临时回收站），**不覆盖 `openclaw-backups/_trash`（保留轮转回收站）**，所以归档轮转只减份数不减占用 —— 2026-11-10 实测该目录四盘合计 1.6T。
- 处理方案待主公拍板（见任务 #972）：`_trash` 内归档满 N 天、且校验到 ≥2 份同尺寸副本后自动删，删前写 sha256 清单。

## 六、回滚
