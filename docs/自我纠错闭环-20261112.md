# 自我纠错闭环（v1.0 · 2026-11-12 主公定调）

> 主公原话：开会就是让你解决这个自我纠错的这个问题。
> 所以决策组不是为了"多人投票"，而是为了**让果果的错有机会在落地前被抓住**。

## 一、我以前为什么纠不了自己的错
1. **我是唯一读到自己结论的人**——没人拿原始输出跟我的说法对账。
2. **没验证的判断和验证过的判断，写出来长得一模一样**——都是肯定的语气。
3. **错了也不留账**——下次同类错误照样犯，因为没人记得上次。
4. **越是自己写的方案，越容易只找支持证据**（确认偏误），而且我看不见自己的盲区。

## 二、闭环的四道闸（全部零 token 或低成本）

### 闸一：议案必须自证事实（已强制）
`tools/decision-pool.py new ... --facts "验过什么、什么命令、什么输出"`
不带 --facts 的 L2/L3 议案**直接拒收**。没验过的只能写成"待验假设"。

### 闸二：独立席位评审（已运行）
GLM / Kimi / DeepSeek 旗舰 三席独立出票，互不可见，各给 kill criteria。
它们最大的价值不是同意，而是**指出我错在哪**——首案就抓住"npm 不可回滚"这个错误说法。

### 闸三：裸断言体检（已强制）
`tools/claim-check.py` 扫"已完成/已生效/已修复/无风险/不易/无法"这类绝对断言，
附近没有证据（命令、输出、rc、pid、sha256）就报错。
`tools/worklog.py` 已接入同一道闸：**带绝对断言又没写 evidence 的入账直接拒绝**。

### 闸四：错误账本 + 月度复盘（已建）
`tools/mistakes.py`：每条错记录"声称什么／实际什么／谁抓住的／加了什么规则"。
每月 1 日 09:00 定时复盘（oc-mistakes-review.timer）：看哪类错在复发、哪些错还没变成规则。
**一个月内同类错误出现两次，就说明规则不咬人，要改机制而不是改说法。**

## 三、谁抓错、抓到后怎么办
- **我自己抓**：写议案时被迫验事实 → 首案就是这样发现 TMPDIR 已生效的。
- **席位抓**：GLM 席抓了"不可回滚"的错误断言。
- **闸门抓**：裸断言入不了账、关单必须跑验收脚本（tasks-db done 已强制）。
- 抓到后的动作固定三步：**作废错误结论 → 写进 mistakes 账本 → 加一条能咬人的规则**。

## 四、已入账的两条真实错误
- M-20261112-001（self）：声称 TMPDIR 未生效，实际今早 09:08 已生效且收益≈0
- M-20261112-002（glm）：声称 npm 升级后不易回滚，实际可固定版本回装

## 五、这套东西的边界（说清楚，别自欺）
1. **它抓不住我们都不知道的事**——三个模型共享相似的训练语料，盲区会重合。
2. **它抓不住我"没写下来"的错**——只在纸面上纠错，心里的错误照样存在。
3. **它有成本**：一次 L3 开会=三次旗舰调用。所以只在"错了代价大"的事上开。
4. **最后仍要靠主公**：随机抽查我一次汇报，比任何机制都硬。
