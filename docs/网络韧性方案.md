# 网络韧性方案（DNS / 路由器重启 / 突发断网）

> 背景：每晚 04:00–06:00 路由器定时重启 → 出口网络中断 → 05:11 那班心跳失败。
> 目标：**分清是谁的问题**，用**最低风险**的手段把影响压到最小。

---

## 一、先把「断网」分成 4 类（探针自动判定）

| 类型 | 现象（探针判据） | 能用「备用 DNS」解决吗 | 对策 |
|---|---|---|---|
| **A 整体断网** | 连路由器 192.168.1.1 都失败 | ❌ 不能（换地址簿无用） | 避峰 + 容忍（重启一般 1–3 分钟） |
| **B DNS 解析失败** | 路由器活着，但解析不出来 | ✅ **能** | **备用 DNS 兜底** |
| **C 出口/上游抖动** | 能解析，但连不上外网 | ❌ 不能 | 重试 + 记录 + 等恢复 |
| **D 单服务故障** | 只有某个服务不可达 | ❌ 不能 | 与我们无关，等对方恢复 |

**自动判定实现**：`tools/net-watch.py`（每段断网都打上 A/B/C 标签）

---

## 二、三个方案（按风险从低到高）

### 方案 1 · 零风险：不改系统 DNS，只「错峰 + 记录 + 报告」
- 做法：心跳限活跃时段 07:00–23:00（已做）；探针记录断网；明早自动汇报
- 优点：**完全不碰系统文件**，零风险
- 缺点：B 类（DNS 卡住）问题还在
- 适用：只要夜间短断网不影响你 → **够用**

### 方案 2 · 低风险（推荐）：固定 DNS，路由器优先 + 公共兜底
- 做法：`/etc/resolv.conf` 写 **路由器 → 阿里 223.5.5.5 → 腾讯 119.29.29.29**，并加 `options timeout:2 attempts:1`
- 为什么这个顺序：路由器放第一 → **局域网名字照旧能解析**；路由器 DNS 卡住时 **2 秒内自动落到公共 DNS**
- 优点：**B 类可解**，且不牺牲局域网解析
- 缺点：需 root 执行一次（脚本已备）；A 类（整体断网）依旧无解
- 执行：`sudo bash scripts/dns-pin.sh --dry-run`（先看）→ `sudo bash scripts/dns-pin.sh`
- 回滚：一键复制备份回去

### 方案 3 · 较重：局域网自建 DNS 缓存（群晖/Windows 那台跑）
- 做法：在内网跑一个 DNS 缓存（指向公共上游），客户端指向它
- 评价：**客户端仍要改 resolv.conf（还是要 root）**，家庭网络收益有限 → **不推荐**，除非以后设备多了

---

## 三、安全底线（不妥协）

1. **绝不给我 sudo 免密**；绝不把密码发到聊天里
2. 系统改动**一律脚本化、可回滚、先 `--dry-run`**
3. **一次只改一处**，改完立即验证解析是否正常
4. 备用 DNS 只作为**兜底**，不夺走路由器的局域网解析职责
