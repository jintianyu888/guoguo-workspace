# 双顾问机制（2026-11-21 主公令）

主公原话要点：干活全用 DeepSeek Flash；还有余额的千问、智谱两个模型，专门成立"两个秘书"，只用来提升方案质量——审方案、补漏、找更优解，可服务任何管家。

## 一、结论：思路对，但有三处必须改

1. **不要建两个常驻 agent**（这次没建）：OpenClaw 新建 agent 必须独占状态、要停网关；而"秘书"本质是"换个模型审一遍"，用模型 + 统一入口就够，还省一份状态与记忆负担。真要常驻，下次重启窗口再议。
2. **两个秘书必须分工，否则就是同一张嘴说两遍**：千问问"有没有更省更快的干法"，智谱问"这方案会怎么死、漏了什么"。
3. **必须带预算和采纳率**：不然一周后就是每天几十次套话评审，钱花了、方案没变好。

## 二、落地形态（已实现）

- 顾问·千问：`qianwen-token-plan/qwen3.8-flash`，专责"更优解 / 替代路径 / 成本收益差"；日预算 20 次
- 顾问·智谱：`zai/glm-5.3`，专责"风险 / 边界 / 合规 / 验收与回滚缺口"；日预算 12 次
- 统一入口：`bash tools/advice.sh <方案文件|-> [--advisor qwen|glm|both] [--goal ...] [--level L1|L2|L3]`
  - 生成两套 prompt（各带专责角度与五段式输出要求）到 `state/advice/<时间>-<顾问>.md`
  - 记一条调用到 `state/advice/calls.jsonl`，超预算直接拒（exit 3）
- 回填采纳：`bash tools/advice.sh --adopt <时间戳> "采纳了什么"`
- 看账：`bash tools/advice.sh --stats`（调用数、采纳率、今日预算）

## 三、什么时候用（触发条件，别滥用）

必须过顾问：
1. 对外发布/对外发送前（合同、公告、群发）
2. 破坏性操作前（删除、迁移、权限变更、重启级）
3. L2/L3 方案首次定稿（议会前先过顾问，别让议会替你做功课）
4. 花钱相关（采购、订阅、充值）

可选：日常小活的心智负担不值得花额度。

## 四、输出契约（写死在 prompt 里）

五段：① 致命问题 ≤3（带触发条件）② 漏项 ≤7（每条一句补法）③ 更优解 ≤3（带成本/风险差）④ 可验收标准（能机器判定优先）⑤ 一句话结论：可执行 / 需修改 / 否决。
硬约束：不夸、不复述；不编数据；引用须给路径，取不到写"不确定"；≤600 字。

## 五、怎么防"顾问变成摆设"

- 每周统计采纳率（`--stats`），连续两周 <30% → 改 prompt 或砍掉该顾问
- 顾问结论必须落到具体改动，否则不算采纳
- 与议会/互审合并：顾问结论进 `state/advice/`，议会直接读，不重复劳动
- 千问 2026-12-01 到期后自动停（预算文件不改也能跑，但会 401，届时切换为单顾问 + deepseek 自审）

## 六、验证

```bash
bash tools/advice.sh --stats            # 显示调用/采纳/预算
printf "方案正文" | bash tools/advice.sh - --advisor both --goal "验收" 
bash tools/advice.sh --adopt <ts> "采纳说明"
```

## 七、回滚

- 删 tools/advice.sh 与 state/advice/ 即完全退出，不影响任何现有流程
- 顾问只是"多审一遍"，不经它也能照常干活

## 八、v1.1 落地：全体管家可直连（2026-11-22 主公令）

主公要求「所有管家都能与秘书配合，产出盲点死角少的结果」。原 v1.0 的入口只生成 prompt，要靠 sessions_spawn 调模型——多数管家 deny 了 sessions_spawn，等于用不了。补直连实现：

- 新入口 tools/advice-ask.py（v1.1）：直接调两家 API，任何管家有 exec 就能用
  `python3 /home/j/.openclaw/workspace/tools/advice-ask.py --plan <方案文件|-> --advisor both --goal "<一句话目标>"`
- 密钥取自 openclaw 密钥库（QIANWEN_PLAN_KEY / ZHIPU_API_KEY），不出本机、不回显
- 结论落 state/advice/<ts>-<advisor>.md，调用与采纳落 calls.jsonl；预算与 advice.sh 共用 budget.json
- 采纳留痕：`--adopt <ts> --note "改了什么"`；不采纳也要在那条记录里写理由
- 同步方式：条款写进 docs/管家通用守则.md「三·五、秘书机制」，用 tools/agent-common-sync.sh --apply 注入 39 个管家 AGENTS.md（当前版本 ad550074）
- 机器稽核：tools/r33-secretary.sh 每日闸门跑，检查条款在、39 家一致、入口可用

实测（2026-11-22 11:39）：千问 38.7s 返回五段结论并指出三处致命问题；智谱 12.1s 返回风险清单。代理链无关，国内直连。

## 六、模型可换（2026-11-22 主公令落地点）

顾问不再是写死在代码里的两个。配置在 `state/advice/advisors.json`：
- 字段：label / kind(anthropic|openai) / url / model / secret(密钥库名) / max_tokens / cap / focus / enabled
- 换模型＝改这一段，不动代码、不重启；
- 加新厂商＝加一段，openai 协议覆盖绝大多数国产接口（豆包、文心、Kimi、MiniMax、Gemini 均可直填）
- `--advisor all` 跑全部启用的顾问；`--advisor a,b` 指定多个
- 预算按各自的 cap 自动生成，新增顾问不会撑破预算逻辑
- 预置未启用槽位：kimi / doubao / ernie / gemini
