# 每日自我提升机制（2026-11-12 主公令立）

> 主公令：你的目的就是不断找寻提升运行系统的「稳定 / 智力 / 能力」的方式方法，
> 给自己不断纠错和提效，这是你每天的任务。

## 一、不喊口号，先量化
工具：tools/self-improve.py（零 token）→ 每天 07:20 由 oc-self-improve.timer 自动跑。
产出：state/improve/metrics-YYYYMMDD.json（逐日留档）+ state/improve/today.txt（人读）

当前采集：
- 稳定：网关状态/重启累计、根分区余量、/dev/shm 使用率、load1、健康探针
- 结构：各节点 connected 状态与掉线时长、任务账本 pending/in_progress/paused、错误账本累计
- 守卫：节点哨兵、暴露面哨兵的最近结论

## 二、三条提升线（明确分工，避免只修修补补）
1. 稳定线：掉线、OOM、磁盘、cron 失败、重启次数。判据是「退化」——与周基线比变差才动手。
2. 智力线：模型选型与路由、评审席位质量、bench 抽样分、幻觉率。
   做法：每周抽 20 题跑 bench，分低于上期就查是路由漂了还是题库变了。
3. 能力线：能做的事变多、变快——新技能沉淀数、技能复用率、单任务耗时、自动化覆盖率。
   做法：每周至少沉淀 1 个技能；每月清一次 45 天未用的技能。

## 三、每天的固定动作（不靠灵感）
1. 07:20 自动量化，出现 [80] 及以上退化项才推飞书（不打扰）
2. 有退化 → 今天第一件事修它，修完写证据入账
3. 没退化 → 今天做「能力线」：把一件重复劳动变成脚本/技能
4. 每天最多开一次议会（按议会政策），L3 每天上限 3 次
5. 23:20 日结时必须能回答：今天系统比昨天强在哪（有数字或证据）

## 四、第一次运行就抓到的真问题（证明这机制有用）
- 误报：把 MyPC-Node 判为「掉线 204 分钟」。真相是 lastConnectedAtMs 是**连上的时刻**，
  不是心跳；连接着的节点这个值也会很旧。已改为用 connected 字段判定 → 错误账本 M-20261112-003
- 连带修正：node-alive-check.py 与 self-improve.py 两处同源错误一起改掉
- 结论：**哨兵本身也要被哨兵盯着**，否则假警报比不报警更坏（会让人开始忽略告警）

## 五、周基线与复盘
- 每周一刷新基线（metrics 的周快照），避免跟自己比烂
- 每月 1 日错误复盘（oc-mistakes-review.timer）+ 技能退休检查（45 天未用）
