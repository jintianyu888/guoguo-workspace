# 浏览器使用与告警降噪规则（2026-11-07 主公令）

## 一、浏览器：能不用就不用，用必关
1. **优先级**：`web_fetch`／curl／API ＞ 浏览器。只有需要登录态、JS 渲染、点击交互时才开浏览器
2. **一次一页**：同一任务只开 1 个页面，禁止并发开多窗口抢内存
3. **用完即关**：任务结束必须关页面；不用 `browser` 就退回，网关不会替你收尾
4. **不许后台常驻**：需要长期跑的采集，改成脚本 + systemd 一次性任务，跑完自己退出
5. **兜底**：`tools/browser-janitor.sh` 每 10 分钟清理僵尸 Chromium（根进程、父进程为网关或已脱离、存活 >15 分钟），阈值总量 2.5GB 时记告警
6. 已知占用：一次 headless Chromium ≈ 3.4GB RSS（24 个进程），不清就是白占

## 二、告警：只报能动手的
1. **额度页登录类不再推送**：zai/minimax 额度页需要扫码/登录时，脚本只写日志（`state/work/quota-scrape.log`）与面板，不推飞书——这类问题没有时效性，推了也只是噪音
2. **强制出处/归属**：每条告警自动带「出处：调用方｜归属：管家」；取不到调用方写「调用方未标注」，不允许空白
3. **噪音类拦截**：notify.sh 内置规则，含「额度页 + 登录/login/扫码」的消息直接落日志不推送
4. **保留推送的五类**：服务不可用、数据风险、安防、花钱、需主公拍板
5. 指标类（温度/内存/缓存/日志量）只进日志与日报

## 三、失败任务处理
- 失败不等到下个周期：空闲即修，修完当场重跑验证 rc=0
- `butler-supervisor.py` 每 20 分钟扫最近 90 分钟失败回执，失败即推一条（同一任务每天一次）
- 连续 2 天同类失败 → 升级为主公待办
