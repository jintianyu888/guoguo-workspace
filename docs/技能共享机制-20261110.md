# 技能共享机制（2026-11-10 立）

起因：主公发现「厨师长能下抖音视频、课时/有用管家下不了」，问技能是不是没同步给所有管家。
结论：确实没同步，而且分成两套，之前只有一套是共享的。

## 一、原来的两类技能

1. **插件技能**：`~/.openclaw/plugin-skills/`，21 个（飞书/企微/浏览器/画布等），由插件提供，**所有管家共享**。
2. **工作区技能**：每个管家自己的 `agents/<id>/agent/workshop-skills/`，**各自私有**。果果有 22 个，其余管家基本是 0。

所以同样 70 个基础技能大家都有，但果果多出 26 个（22 个 workshop + 其他），别人一个都看不到。

## 二、为什么软链不行（踩过的坑）

OpenClaw 把每个技能根目录当安全边界：`<workspace>/.agents/skills` 下的软链，如果真实目标在根外，会被直接跳过（日志关键词 `reason=symlink-escape`）。
实测：软链到 `/home/j/.openclaw/shared-skills` 的 9 个技能，只有先前以实体目录存在过的那个被索引到，其余全部不可见。

## 三、现在的做法（唯一正确姿势）

- 主本目录：`/home/j/.openclaw/shared-skills/`（实体文件，22 个技能）
- 配置：`skills.load.extraDirs = ["/home/j/.openclaw/shared-skills"]`
- 效果：所有管家读同一份，改一次全体生效；不需要重启网关，**新会话即生效**（老会话要重开）
- 管理脚本：`bash tools/skills-sync.sh`（列出+抽查）、`--add <技能目录>`（发布）、`--rm <名字>`（撤下）

验证口径：`openclaw skills --agent <id> --json | jq '.skills|length'`，改前 70，改后 92（cooking / class-schedule / useful 三处实测）。

## 四、共享清单（22 个）

运维类：deletion-to-trash、host-process-health-check、stalled-large-download、gateway-resource-safety、session-compaction-recovery、agent-provisioning、script-inventory-audit、project-monitoring、risk-tier-routing
媒体类：video-download（新增）、inbound-media-understanding、voice-reply-delivery
业务类：feishu-report-automation、feishu-troubleshooting、wecom-connection、booklet-printing、tailscale-funnel、local-gpu-acceleration
模型/备份类：model-switching、model-key-rotation、backup-pipeline-audit、openclaw-backup-recovery

不下放：`reply-footer-metrics`（页脚只允许维护管家附加，留在 main 私有）。

## 五、顺手修的配置错误

`openclaw.json` 里 `models.providers.deepseek.models[0/1].thinkingFormat` 是当前版本不认识的老键，导致所有 `config patch` 被拒（invalid config）。已备份后移除两个键（备份：`state/backup/openclaw.json.bak-*`），patch 才通过。

## 六、回滚

- 撤销共享：删 `skills.load.extraDirs` 这一项 → 各管家回到只读自己工作区
- 撤销新技能：`bash tools/skills-sync.sh --rm video-download`
- 撤销配置修复：用 `state/backup/openclaw.json.bak-*` 覆盖（不推荐，会让 config patch 再次失效）
## 盘点补充（2026-11-10 20:40 果果）

- `skills.load.extraDirs` 会被网关整份配置回写覆盖丢失（今天已发生两次）。已重新 patch 并实测：`openclaw skills list --agent backup` 可见全部共享技能；`tools/skills-sync.sh` 每次先复查此项。
- main 的 workshop-skills 副本优先级高于 extraDirs，共享主本更新后 main 仍读旧版（video-download 曾差一个版本）。新增 `tools/skill-mirror.sh`，`skill-update.py` 更新后自动镜像。
- 退休判定改为按首见日：`state/skills/registry.jsonl` 记录 first_seen，`tools/skill-audit.py` 算未使用天数。技能库首见 2026-11-10，首次 45 天审查日 2026-12-25。
- `skill-usage.py report` 原先把「从未使用」一律当「N 天未用」，新建技能一出生就被判老；已改为按首见日算，未到期算正常。
