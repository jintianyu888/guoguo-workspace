# 用量快照超时 —— 根因与修复（2026-11-21）

## 现象
"每日用量快照(v2)" 连续 4 次超时（11-17 ~ 11-20），报 `cron: job execution timed out (last phase: tool-execution-started)`；state/usage/ 缺 11-17~11-20 四天文件，usage-snapshot.log 停在 11-16。

## 根因（模型管家排查，果果复核）
不是 SQLite 慢读，是 **exec 卡在人工审批**：
- `agents.entries.model.exec.mode = "ask"`（全库只有 model 与 class-schedule 是 ask，其余 allowlist/deny）。
- 该身份同时缺 scope `operator.approvals`，审批注册直接失败，cron 里无人可批 → 挂到超时（30 分钟）。
- 证据：失败 session 第 2 条消息即 exec 调用，22:39:55 → 23:19:54 零 tool result；脚本本身一次都没跑起来（日志无 "FAIL python 采集失败"）。
- 补 safeBins 治不好：`bash <script>` 这种 shell 包装按文档仍需人工审批，不吃 safeBins 自动放行。

## 修法（A 案：采集搬出 agent）
1. 采集改由 systemd 用户定时器跑，零审批零 token：
   - `~/.config/systemd/user/oc-usage-snapshot.service`（oneshot，TimeoutStartSec=600，Nice=10）
   - `~/.config/systemd/user/oc-usage-snapshot.timer`：每日 **21:20**（避开 21:35 周计划、21:42 汇报）
   - 已 enable，下次 21:20 触发；脚本失败走脚本内置 notify.sh。
2. cron 任务 `1b1a549f-d38f-4a97-9e0b-a5176e4f9332` 改成**只读汇报**：
   - 名称：每日用量快照汇报(v2·只读)；21:42 不变；payload = command
   - 执行 `tools/usage-report.sh`（读 state/usage/<date>.json → 打印总量/前 5/日对比，缺失照实报"缺失"，rc 恒 0，不再装红）
   - 实测：12:02:22 手动触发，status=ok，0.9s。
3. 今日快照已补采：state/usage/2026-11-21.json（总量 54.27 GB / 188328 事件）。
   11-17~11-20 四天无法补（脚本只写当日），记为历史缺口。

## 不采纳 / 已知
- 未给 model 身份加 `operator.approvals`，也未改 mode=allowlist：审批权限属权限扩容，且 A 案已解根因。若模型管家今后确有 shell 需求，走 allowlist 白名单单条申报。
- class-schedule 同为 ask 但无 cron 任务，无风险。
- `automations` 工具当前坏：list 返回不满足自身 outputSchema（缺 jobs/total/offset/limit/hasMore），任何 job 里调用都会踩；已记入待修。

## 回滚
```
systemctl --user disable --now oc-usage-snapshot.timer
rm ~/.config/systemd/user/oc-usage-snapshot.{service,timer} && systemctl --user daemon-reload
openclaw cron edit 1b1a549f-d38f-4a97-9e0b-a5176e4f9332 --message "<原 agentTurn 正文>"
```
