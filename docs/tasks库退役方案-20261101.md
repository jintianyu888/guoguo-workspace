# tasks 库退役方案 v0.2（2026-11-01）

> v0.1 被 minimax/MiniMax-M3 否决（REJECT，8613B）。否决理由成立，本版据此重写。
> 核心修改：取消双写模式；旧库在读者切换前先锁成只读，让残留写路径当场失败；判定标准由"汇总值"升级为"集合级+字段级+写入路径覆盖"。

- ledger.db tasks 表：5 列，已补齐至 214 行（#208–#218 共 11 条 done）
- 写入方 2 个：tools/tasks-db.py（18 处写）、tools/ledger-park.py（1 处）
- 读取方 7 个：morning-plan.sh（07:00 早报）、day-plan.py、plan-report.py、plan-guard.py、plan-retro.py、plan-roll.py、maint-db-read.sh

## 二、v0.1 的三处致命缺陷与修法

| 缺陷 | v0.1 做法 | v0.2 修法 |
|---|---|---|
| 残留写路径导致静默分叉 | 切写方，保留 --legacy 双写 | **取消双写**；切完立即 chmod 0444 旧库，残留写路径当场报错 |
| 对照标准太弱 | 行数/状态分布/未结数 | 集合级 + 字段级 + 写入路径覆盖（见四） |
| 分叉无即时告警 | 每日离线比对 | 只读锁把"分叉"变成"报错"，无需事后发现 |

## 三、步骤（顺序不可调整）

### 步骤 0：全量备份
cp tasks.db 与 ledger.db 至 state-backups/，并记录 sha256。回滚基准。

### 步骤 1：扩表（L1）
ledger.db tasks 表 ALTER TABLE ADD COLUMN 追加 12 列：
no, kind, grp, prio, notes, created, updated, closed_by, blocked, blocked_reason, blocked_until, block_owner, who, agent。
只加列不改数据。SQLite ADD COLUMN 不接受非常量默认值与非空无默认，一律允许 NULL。
注意：既有 5 列 reader 用 SELECT * 的脚本会多拿列，切换前先 grep 确认无位置依赖。

### 步骤 2：切换写入方（L2）
tasks-db.py 的 18 处写、ledger-park.py 的 1 处写，全部改指 ledger.db。
**不做双写、不保留 --legacy 回写。**
改完逐个执行一次写操作并立即读回验证。

### 步骤 3：旧库上线只读（关键，取代原"归档"）
chmod 0444 state/tasks/tasks.db（并 chmod a-w 目录项防重建）。
此后任何残留写路径会直接 permission denied 并在日志暴露，而不是悄悄写进旧库。
这是本方案的核心保险：**分叉从"难发现"变成"立刻报错"**。

### 步骤 4：切换读取方（L2）
先 3 个低频（plan-retro / plan-roll / maint-db-read），各改完立刻跑一次并比对输出。
再 4 个高频（morning-plan / day-plan / plan-report / plan-guard），逐个切换，逐个比对。

### 步骤 5：对照观察 3 天
每天用四节的三级判定全跑一遍。连续 3 天全通过才进入步骤 6。

### 步骤 6：归档
按原计划移入 state-backups/tasks.db.retired-202611，保留 0444，不删除。

## 四、判定标准（三级，缺一不可）

1. **集合级**：两库按 task_id 对齐，主键集合必须完全相同。禁止只比总数——总数相同可能增删抵消。
2. **字段级**：对每条任务比较规范化后的全部业务字段（title/status/kind/prio/notes/verify/agent/blocked 等）。规范化 = 去首尾空白 + 空串与 NULL 归一。
3. **写入路径覆盖**：把 18 处写操作逐个执行一遍（在临时副本上），每次写完立即比对两库；任何一条未覆盖即判不通过。

不允许用"行数相同""状态分布相同"单独作为通过依据。

## 五、回滚

任一步失败：恢复步骤 0 的 db 备份 + 恢复对应脚本备份，chmod 644 旧库。
全量回滚约 2 分钟，不涉及数据丢失（旧库全程未被修改）。

## 六、最大风险（v0.2 自评）

步骤 3 上线只读后，若某条写路径在步骤 2 被漏掉，该功能会**直接报错**而非静默降级——这是有意的。
风险是用户可能在下一次用到该功能时才发现。对策：步骤 2 完成后立刻全量 grep 一次写语句，并在 24 小时内跑一遍日常操作。

## 七、不做的事

- 不删除任何数据
- 不保留双写开关
- 不在三级判定未连续 3 天通过前归档
- 不动 tasks.json（导出件，只读）
