# 多机节点方案（C 机存储整理 / D 机外网笔记本）2026-11-11

## 目标
一个大脑（A：WSL 网关）统管全部机器；C、D 只做「手和眼」，不各自跑 agent、不各自升级。

## 现状
- A = 本机 WSL，网关 18789，bind=lan，token 鉴权（密钥在 secrets store）
- A 的 WSL IP = 172.18.242.44（NAT，非局域网可直连地址）
- B = 已配对节点（MyPC-Node，Windows 宿主）
- C = 电影/书籍存储机，现跑着自己的 OpenClaw，升级反复卡住，用途：整理硬盘、片库、去重、备份
- D = 笔记本，不在同一局域网，用途待定

## 关键结论：C 的「升级总卡」根因不在升级本身
C 现在跑的是完整网关（agent + 数据库 + 迁移），每次升级都要过 DB schema 迁移。
如果 C 只做**节点**（node host），就没有 agent 状态、没有 DB 迁移，升级退化成「一个 npm 包换个版本」，
就算卡也只影响执行，不会把机器搞崩。所以第一步是把 C 从「网关」降级为「节点」。

## 拓扑

## 怎么连（问题在 A 这一侧）
A 在 WSL NAT 里，局域网和外网都到不了 172.18.242.44。两条路：

### 方案一（推荐）：Windows 宿主做转发 + Tailscale
1. Windows 上开端口转发（管理员 PowerShell，一次性）：
   netsh interface portproxy add v4tov4 listenport=18789 listenaddress=0.0.0.0 connectport=18789 connectaddress=<WSL_IP>
   （WSL IP 每次重启变 → 配一个开机计划任务刷新这条规则）
2. Windows 装 Tailscale，D 机也装 Tailscale 并加入同一 tailnet
3. 结果：
   - C（同局域网）直连 http://<Windows局域网IP>:18789
   - D（外网）连 http://<Windows的tailscale IP>:18789
   - 全程走 token 鉴权，流量在 tailnet 内加密
4. 风险：暴露 18789 到局域网（token 保护）；Tailscale 只装不启用 Exit Node

### 方案二：WSL 镜像网络（更彻底，改动大）
.wslconfig 加 networkingMode=mirrored，WSL 直接共享宿主 IP，不需要 portproxy。
代价：网络栈变化可能影响现有 B 节点和 127.0.0.1 端口假设，需要一次完整回归测试。

### 方案三：不动 A，只在 C/D 侧用反向隧道
frp / Cloudflare Tunnel 从 C/D 连出去。需要 A 上有公网可达入口，本机没有 → 不推荐。

## C 机落地步骤（同局域网，最快）
1. C 上停掉自己的网关：openclaw gateway stop / 禁用其服务（保留配置备份）
2. C 装 node host：npm i -g openclaw && openclaw node install（或 openclaw node run 先前台验证）
3. 在 A 上生成配对：openclaw node pair（按提示确认），C 侧 --gateway-url http://<A可达地址>:18789 --token <网关token>
4. 能力收窄：只开 system.run + 文件读写白名单目录（片库根目录、备份目标）
5. 装整理所需工具：python3、ffmpeg/ffprobe、rclone、（可选）dupeguru 或自写去重脚本
6. 冒烟：从 A 通过节点跑 ls/df/ffprobe，确认路径正确

## D 机落地步骤（外网笔记本）
1. 装 Tailscale 并登录同一 tailnet（D 与 Windows 宿主各一个节点）
2. 装 node host，用 Windows 的 tailscale IP + token 连接
3. 能力最小化：只开 system.run，文件能力默认关；用途定了再开
4. 笔记本合盖/休眠会让节点掉线，需要时用 openclaw node restart

## 安全边界
- 节点不是网关：节点只能执行 A 发下去的命令，不能自己发起任务、不能读 A 的密钥
- 能力按需开，默认最小；C 只白名单片库目录，D 默认无文件权限
- 只允许 tailnet 内或局域网访问，不做公网端口暴露（Cloudflare 公网 URL 不用）
- 所有节点操作入账 state/log/worklog.jsonl
