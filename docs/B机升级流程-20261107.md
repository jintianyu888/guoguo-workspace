# B 机升级流程（agent 执行版）— 2026-11-07

## 为什么不是纯 bash
A 侧 CLI 无法在 B 上执行 shell：`openclaw nodes invoke --command system.run` 被明确拒绝
（"system.run is reserved for shell execution; use the exec tool with host=node"）。
node 暴露的命令只有 system.which / fs.listDir / ollama.* / terminal.upload / desktop.stream 等，没有通用 shell。
所以 B 的升级必须由 agent 用 exec host=node 执行，不能写进 upgrade-panel.sh 自动跑。

## 执行步骤（agent 照做）
1. 读当前版本：exec host=node，命令 `cmd /c openclaw --version`，记为 BEFORE
2. 与 A 的目标版本比对；相同则结束，回报已是最新
3. 安装：exec host=node，命令 `cmd /c npm i -g openclaw@TGT --no-audit --no-fund`，timeout 900s
4. 重启 node 服务：`cmd /c schtasks /end /tn "OpenClaw Node"`，sleep 3，`cmd /c schtasks /run /tn "OpenClaw Node"`
5. 验证：等 node 回连（nodes.list connected=true）后重查版本是否等于 TGT；否则报失败

## 已知坑
- B 的 powershell.exe 从 node 通道调用会挂起（实测多次）；一律用 cmd，不要用 powershell
- B 没有 wmic；查磁盘用 `fsutil volume diskfree C:`
- npm 全局目录：C:\Users\金鱼\AppData\Roaming\npm；计划任务名：OpenClaw Node
- 升级前确认 B 不在跑本地模型（curl /api/ps 为空），否则重启会打断推理

## 回滚
B 侧 npm 回退：`npm i -g openclaw@旧版本` 后重启计划任务
