# 统一账本与记录规则（2026-11-10 主公令）

主公 2026-11-10 19:25 令：以后做的所有事情，都要写入一个统一的账本 / 记录 / 说明。
本文件是唯一口径，四个层次各有分工，不许只用其中一层就交差。

## 一、四层结构

1. **任务账本** `state/tasks/tasks.db`（唯一真源）
   - 谁做、什么时候做、做到哪一步、怎么算完成（verify）、卡在哪。
   - 视图 `state/tasks/tasks.json` 由 tools/tasks-db.py export 生成，给面板/页脚读。
2. **工作日志** `state/log/worklog.jsonl`（每次动手都写）
   - 一条 = 一个动作：时间、类别（fix/change/cleanup/deploy/decision/incident/verify/note/plan）、对象、一句话结果、证据、回滚方式、关联任务号。
   - 追加写、带前序哈希链（`prev` + `hash`），事后改一行就断链。
   - 工具：`python3 tools/worklog.py add <类别> <对象> <结果> [evidence=] [rollback=] [task=]`
3. **领域账本**（机器可查，按领域分）
   - 备份：`state/backup/archive-purge-ledger.jsonl`、`state/backup/backup.db`
   - 告警：`state/alerts/*`；额度：`state/model-econ/*`；评分：`state/plan/*`
4. **说明文档** `docs/*.md`
   - 规则、方案、复盘、口径变更。凡是“以后都这么做”的，必须落成文档，不能只在对话里说过。

## 二、什么必须入账

- 改了脚本 / 配置 / cron / 权限 → 必须（含改完怎么验的）
- 删了数据 / 清了空间 / 迁移了目录 → 必须（含删了什么、释放多少、能不能回滚）
- 部署、对外连接、拉新凭据 → 必须
- 做了决定、推翻了旧口径 → 必须（decision）
- 出故障、定级、恢复 → 必须（incident + fix 两条）
- 关任务 → 必须带 task= 号，让日志和账本对得上

纯读取、纯查询、聊天问答不记。

## 三、自动化（不靠自觉）

- 每日 20:30 简报带一行「▍记录」：今日日志条数 + 未挂 task= 的关单数。
- 每日 23:20 `github-sync.sh` 提交前自动 `worklog.py render`，把 `docs/工作日志-YYYY-MM.md` 一起进私有仓，历史可追溯。
- `worklog.py check` 随时自查：今日条数、关单未入账清单。
- 月度日志 md 是从 jsonl 整体重渲染的，**禁止手改**。

## 四、回滚

- 日志是追加写，删错条目只能追加一条更正（不许改历史行）。
- 撤销整套机制：删 `tools/worklog.py`、`state/log/`、`docs/工作日志-*.md`，并回滚 `tools/github-sync.sh` 与 `tools/daily-briefing.py` 里带「2026-11-10 主公令」注释的块。
