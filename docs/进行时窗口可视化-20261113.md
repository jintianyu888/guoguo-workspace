# 进行时窗口可视化（重启/备份/掉线）—— 2026-11-13 23:10

## 为什么做
主公 22:56 令：「你下次重启、备份、全量备份，给我一个预警窗口和窗口进度条，或者一个我能看见的东西，要不然我以为你又崩溃了。」

## 三层可见性
1. **提前预警**（飞书，走果果主应用）
   - 07:30 重启预告（oc-presage-restart.timer）
   - 00:50 备份预告（oc-presage-backup.timer）
2. **进行时大浮层**（面板 http://127.0.0.1:8899，屏幕中央卡片）
   - 青卡：备份中 / 重启中，大号百分比 + 22px 粗进度条 + 已运行/预计剩余
   - 红卡：主脑（网关）无响应 —— 面板仍在跑说明不是整机崩溃
3. **关键节点飞书**：开始 / 过半 / 完成 / 失败，各一条，不刷屏

## 组件
- `tools/activity.py` —— 唯一状态文件 `state/status/activity.json`（kind/phase/percent/eta/started_at/updated_at），另存 `activity.log.jsonl` 历史
- `tools/activity-watch.py` —— 每 2 分钟（oc-activity.timer）：
  - 备份：pgrep `daily-backup.sh`（正则 [d] 避免自匹配）或 `/mnt/d/openclaw-backups/*.tar.gz` 10 分钟内仍在增长 → 从 `state/work/bk-run.log` 阶段映射百分比（1/5=8、2/5=20、打包完成=45、整文件复制=55、4.5/5=88、5/5=95）
  - 重启：`state/work/.restart-in-progress` 标记存在且 <15 分钟
  - 空闲：清残留，防"永远显示备份中"
- `tools/activity-presage.sh` —— 预告文案（restart/backup 两个分支）
- 面板：`server.js` 新增 `/api/activity`；`public/index.html` 末尾插入居中浮层 + 20 秒轮询
- `tools/restart-window.sh` —— 重启前写标记 + 发「即将重启」，health 200 后发「已恢复」并清标记

## 验证
- `python3 tools/activity.py set kind=backup phase=测试 percent=42` → `curl /api/activity` 返回一致
- 面板整页 200，内联脚本通过 `node --check`
- `tools/activity-watch.py` 空跑 0.07s，无备份时自动清成 idle

## 已知边界
- 整机断电/Windows 重启时面板也一起停，无法显示（这是客户端侧只能靠"下次上线报平安"兜）
- 备份百分比是阶段+体积估算，非逐文件精确计数；跨盘复制阶段按阶段跳变
- 进度类飞书走果果主应用；告警类仍按 2026-10-31 令走维护管家（主公 23:03 明确要求不改）

百分比规则：能从日志拿到阶段就用阶段值；否则按「已运行/预计」线性推算，封顶 92%，避免假装跑完。

坑：`pgrep -af` 会匹配到调用它的父 shell（命令行里含同样的字样），造成"永远有备份在跑"。修法＝模式串必须带 `.sh`/`.py` 后缀，且排除含 `pgrep` 或 `activity-watch` 的行。

掉线卡只在面板自身存活时才可能显示；整机断电时面板一起消失，无法显示（已在卡片文案里写明）。
