## 二、分工（谁管什么）

### 模型管家（model）—— 侦察兵 + 计量员
1. **发现**：每周一读 tools/model-radar.py 产出（state/model-radar/），挑出 3 个与我方任务最相关的候选，写一页对比（能力/价格/上下文/可用性）。
2. **评测**：对候选跑固定任务集（同一批 12 道题：中文长文摘要、代码修复、多步工具调用、结构化抽取），记录质量分与单任务成本。任务集固定，不许每次换题。
3. **台账**：维护 state/work/model-bench-b.md 与 docs/模型评测台账.md（速度/显存/中文/视觉四项必须齐）；登记每次换模型的日期与理由。
4. **计量**：额度采集每日一次（qianwen 必须补上，读不到就标注「未采集」并说明原因），越线告警。
5. **探活**：每日各 provider 可用性探测，失败连续 2 次上报果果。

### 果果（main）—— 决策 + 路由 + 钱袋
1. **路由策略**：哪个档走哪个模型、时段怎么切、兜底链怎么排（写进 model-slot.sh 的链条常量，不许手改配置文件绕过）。
2. **成本闸门**：预算与半价窗（DeepSeek 00:30-08:30 半价）、高峰 token 闸门、批量任务排队。
3. **换不换**：拍板。判据见第四节。拍板前必须看到模型管家的评测数据 + 回滚方案。
4. **验收**：切换后 24h 观察失败率、平均延迟、成本曲线；不达标回滚。
5. **审计**：抽查台账真实性（不许自评自证），每月一次与雷达产出对账。

### 交接点（硬性）
- 周一 09:00 雷达 → 模型管家 24h 内出候选评估 → 果果 48h 内给结论（换/不换/观察）。
- 结论必须落 docs/模型评测台账.md，写清「测了什么、结论、回滚命令」。
- 谁都不许跳过评测直接换主力模型。

- **每季度**：基线重定 —— 清掉表现差的模型、重排评审池、复核本地模型是否还值得留
- **触发式**（不等日历）：厂商大幅降价、停服/限流、我们连续 3 天失败率抬头、额度 7 天内将耗尽

## 四、换模型的判据（防止拍脑袋）

满足其一才换：
1. 同任务集质量 ≥ 现役 +5 个百分点，且单任务成本 ≤ 现役 80%
2. 质量持平（±2pp 内），单任务成本 ≤ 现役 60%
3. 现役模型被停服/限流，或连续 3 天失败率 > 5%

任何切换必须带：回滚命令、观察窗口（24h）、验收指标（失败率、P95 延迟、成本/天）。
判定不达标就在 24h 内回滚，不许「再观察几天」。
