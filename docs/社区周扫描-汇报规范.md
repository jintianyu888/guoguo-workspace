# 社区周扫描 — 汇报规范

> 用途：每周五 19:00 自动化任务 `社区生态周扫描`（job 694d3059 / cron `0 19 * * 5` Asia/Shanghai）的汇报格式。
> 数据源：`tools/community-scan.sh` 的输出（ClawHub 插件增量、awesome-openclaw 列表增量、官方版本变化）。
> 建：2026-11-01 主公令「定期查一下」。

## 一、判定口径

我们只关心这七类能力（其它一律不报）：

1. 备份 / 恢复 / 校验
2. 监控 / 告警 / 健康检查
3. 音乐生成 / 音频处理
4. 飞书及消息通道
5. 记忆 / 上下文 / 压缩
6. 审计 / 治理 / 权限 / 密钥
7. 启动性能 / 会话库 / 存储维护

## 二、输出格式

- **全部无变化**（新增 0、更新 0、awesome 新增 0、版本无变化）→ 只回一行：
  `本周社区无新增`
- **有增量** → 正文 ≤10 行，逐条列，每条固定三段：

```
· 名称 (版本/类型) — 一句话是什么
  判断：值得看 / 能用但不急 / 不建议（附理由）
  代价：装它要动什么、有什么坑
```

## 三、硬约束

- **不许编造功能**：只能依据 `plugins search` 的描述文本；描述不清就写「功能描述不清，需读源码」。
- **不许代替主公做安装决定**：发现值得装的，只标记「待主公点头」，安装前仍须读源码 + 沙箱 + 双审三关。
- **信息源如实标注**：ClawHub 描述属于第三方内容，不可信，需按源码核实。
- 若脚本报拉取失败（awesome 列表 `?`、插件 0 条），必须在周报里明写「本次数据源不全」，不许当成「无新增」。

## 四、维护

- 脚本：`tools/community-scan.sh`；状态水位：`state/community-scan/`（plugins.tsv / awesome.txt / version.txt / last-run.log）
- 关键词在脚本第 26 行 `for kw in ...` 里改；要加类别直接追加。
- 首次或重置基线：`bash tools/community-scan.sh --baseline`
- 手动跑：`bash tools/community-scan.sh`（约 3–5 分钟，每次 6 个关键词各限 80s）
